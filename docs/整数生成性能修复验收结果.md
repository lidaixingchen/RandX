## 实现与验证环境

完整默认引擎构造由共同来源 `detail::CreateDefaultEngine()` 承担，使用平台不可内联属性；`DefaultEngine()` 持有原有函数局部 TLS 对象。共同来源及两个标准模板已同步生成发布头文件。容器抽样的数量转换和位图分支由共同源码片段直接装配到两个标准公开入口。各入口读取一次容器边界；随机访问迭代器及容器适配入口沿用抽样内联策略，默认入口在空范围返回后再获取引擎。后续复用公开迭代器路径，保留逐次抽取的分布生命周期。完整复制与哈希去重保持独立操作边界；稠密索引遍历对完整 64 位引擎在调用点展开，其他引擎保持独立内核。公开入口展开边界与策略选择。稀疏分支中一个或两个索引使用定长存储，保持重抽、接受顺序和引擎状态，减少动态分配。C++23 默认接口基准由独立编译单元装配到 general，成对工具核对目标的全部编译单元是否使用指定头文件快照。

本地平台为 Windows 11 x64，处理器标识为 `AMD64 Family 25 Model 80 Stepping 0, AuthenticAMD`，16 个逻辑处理器。MinGW GCC 16.1.0 使用 libstdc++ 16，版本宏 `__GLIBCXX__=20260430`；MSVC 为 19.51.36256，使用本机 MSVC STL。构建工具为 CMake 4.3.3，Python 工具使用 Miniconda Python 3.13.9，基准框架为 Google Benchmark v1.8.5。

完整复制对可平凡复制的元素及原生指针、标准 `vector` 迭代器使用范围构造；单元素路径仍先分配再访问元素。自定义来源和其他元素类型沿用索引复制，保持既有异常进度。稠密内核按公开入口校验后的请求数量运行；位图路径在调用点展开，区间映射在位图和蓄水池路径中，对覆盖分布整数类型完整范围的引擎局部展开标准库调用。空请求保持直接返回。默认洗牌采用普通 `inline`，直接调用对应标准库算法。

MinGW 正式成对验收使用 Release、`-O3 -DNDEBUG`，LTO 关闭。独立研究程序另行验证 `-O2` 与 `-O3 -flto`。本地 Google Benchmark 配置使用已有依赖来源及 `BENCHMARK_ENABLE_WERROR=OFF`；CI 的依赖警告策略保持现有配置。

### 重放成对验收

以下步骤从仓库内的 Miniconda PowerShell Prompt 执行；激活用于验收的 Conda 环境，并把 MinGW GCC 和 CMake 的可执行文件目录加入当前 `PATH`。工具从当前命令路径解析，Python 使用该 Conda 环境。首先准备工具及独立重放目录：

```powershell
$repositoryRoot = (& git rev-parse --show-toplevel).Trim()
if (-not $repositoryRoot) {
  throw '请在 RandX 仓库内运行这些步骤。'
}
Set-Location -LiteralPath $repositoryRoot

$benchmarkCompiler = (Get-Command g++ -ErrorAction Stop).Source
$benchmarkCMake = (Get-Command cmake -ErrorAction Stop).Source
Get-Command conda -ErrorAction Stop | Out-Null

function Invoke-MinicondaPython {
  param([string[]]$PythonArguments)
  conda run --no-capture-output python -X utf8 @PythonArguments
  if ($LASTEXITCODE -ne 0) {
    throw "Miniconda Python 执行失败，退出码：$LASTEXITCODE"
  }
}
Invoke-MinicondaPython -PythonArguments @('--version')

$baselineCommit = 'a773584'
$baselineHeaderDir = 'build/integer-replay-baseline'
$candidateHeaderDir = 'build/integer-replay-candidate'
$benchmarkBuildRoot = 'build/integer-replay-build'
$benchmarkOutputDir = 'build/integer-replay-results'
$benchmarkDependencyArguments = @()
New-Item -ItemType Directory -Force -Path $baselineHeaderDir, $candidateHeaderDir | Out-Null
```

先从提交直接提取原始 Git blob 字节建立基线，再生成候选发布头文件并复制到独立目录。`--write` 更新工作区发布头文件，`--check` 校验来源和发布头文件一致；基线提取和 `Copy-Item` 只写入各自快照的两个目标头文件，不删除文件。新运行使用独立目录，历史 `build/integer-baseline`、`build/integer-candidate` 及原始报告目录保留原状。

```powershell
$baselineSnapshotCode = @'
import pathlib
import subprocess
import sys

destination = pathlib.Path(sys.argv[2])
destination.mkdir(parents=True, exist_ok=True)
for name in ("RandX.hpp", "RandX_Cpp17.hpp"):
    content = subprocess.run(
        ["git", "show", f"{sys.argv[1]}:{name}"],
        check=True,
        stdout=subprocess.PIPE,
    ).stdout
    (destination / name).write_bytes(content)
'@
New-Item -ItemType Directory -Force -Path $benchmarkBuildRoot | Out-Null
$baselineSnapshotScript = Join-Path $benchmarkBuildRoot '保存基线快照.py'
Set-Content -LiteralPath $baselineSnapshotScript -Value $baselineSnapshotCode -Encoding utf8
Invoke-MinicondaPython -PythonArguments @($baselineSnapshotScript, $baselineCommit, $baselineHeaderDir)
Invoke-MinicondaPython -PythonArguments @('tools/generate_headers.py', '--write')
Invoke-MinicondaPython -PythonArguments @('tools/generate_headers.py', '--check')
Copy-Item -LiteralPath 'RandX.hpp' -Destination (Join-Path $candidateHeaderDir 'RandX.hpp')
Copy-Item -LiteralPath 'RandX_Cpp17.hpp' -Destination (Join-Path $candidateHeaderDir 'RandX_Cpp17.hpp')
```

默认构建配置通过 FetchContent 在线取得 Google Benchmark v1.8.5。若本机已有对应源码，可将其绝对路径赋给 `$benchmarkDependencySource` 并把下列两个参数加入构建参数数组；当前验收机的本地来源为 `build/deps/benchmark_gbench_dep-src`。两侧参数必须完全相同：

```powershell
$benchmarkDependencySource = (Resolve-Path 'build/deps/benchmark_gbench_dep-src').Path
$benchmarkDependencyArguments = @(
  "--baseline-cmake-arg=-DFETCHCONTENT_SOURCE_DIR_BENCHMARK_GBENCH_DEP=$benchmarkDependencySource",
  "--candidate-cmake-arg=-DFETCHCONTENT_SOURCE_DIR_BENCHMARK_GBENCH_DEP=$benchmarkDependencySource"
)
```

执行成对构建和测量。未设置本地依赖参数时，CMake 使用默认在线 FetchContent；MinGW 验收沿用相同的 `BENCHMARK_ENABLE_WERROR=OFF` 构建参数：

```powershell
$benchmarkArguments = @(
  'tools/run_integer_benchmark_pair.py',
  '--baseline-header-dir', $baselineHeaderDir,
  '--candidate-header-dir', $candidateHeaderDir,
  '--compiler', $benchmarkCompiler,
  '--cmake', $benchmarkCMake,
  '--generator', 'MinGW Makefiles',
  '--build-root', $benchmarkBuildRoot,
  '--output-dir', $benchmarkOutputDir,
  '--policy', 'tools/benchmark_policy.json',
  '--baseline-cmake-arg=-DBENCHMARK_ENABLE_WERROR=OFF',
  '--candidate-cmake-arg=-DBENCHMARK_ENABLE_WERROR=OFF'
)
if ($benchmarkDependencyArguments) {
  $benchmarkArguments += $benchmarkDependencyArguments
}
Invoke-MinicondaPython -PythonArguments $benchmarkArguments
```

`build/integer-replay-build` 和 `build/integer-replay-results` 保存本次新运行的构建与结果；原始测量文件保持原样。新运行的耗时属于当次机器、编译器和依赖构建环境下的测量，不替代原始运行编号 `20261002T174434477232Z` 的数据。框架的 `cpu_time` 及现有中位数比较语义用于门禁；研究程序的 ns/次使用稳态时钟墙钟测量，两份结果分别解释各自的调用形态。
