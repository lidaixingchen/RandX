# 共同源码迁移清单

## 默认引擎构造与线程状态

`common/engines/create_default_engine_definition.inc` 维护 `detail::CreateDefaultEngine()` 的完整定义及平台不可内联属性。两个标准的 `security_and_seeding.inc` 在 `RandomSeed()` 定义后、公开默认引擎文档前引入该片段。`common/engines/default_engine_definition.inc` 维护 `DefaultEngine()`，通过辅助函数初始化原有函数局部线程对象。

构造辅助函数返回引擎值，线程状态只由 `DefaultEngine()` 持有。共同契约位于 `tests/common/default_engine_contracts.hpp`，生产与熵源 hook 配置分别在两个标准的独立目标中验证序列、播种、跨翻译单元实体及线程隔离；入口与桥接位于 `tests/default_engine/`。

## 批次 B：抽样与数值分布

### 抽样位图与分布生命周期

- 来源位置：`RandX.hpp` 原始 2667–2737 行；`RandX_Cpp17.hpp` 原始 2749–2819 行，位于 `namespace RandX::detail` 的抽样内核区。
- 共同定义：`ValidateSampleSize`、`SampleBitmapWordBits`、`SampleBitmapThresholdK`、`SampleBitmapDensityDivisor`、`SampleBitmap`、`SampleDistributionLifetime::{Selection, Draw}`，`IsEmptySampleRequest`、`DrawSampleDistribution`、`DrawFullRangeSampleDistribution`、`DrawReservoirSampleIndex`，以及 `SampleFixedIndexDistribution` 的前置声明和两个特化类。完整定义组位于 `common/sampling/sample_bitmap_and_lifetime.inc`。该片段引入 `common/sampling/sample_linear_indices.inc`，共同维护 `SampleLinearIndexCapacity`、`SampleSingleValueCount` 与 `SampleLinearIndices`；稀疏分支中一个或两个索引采用定长存储，复用对应分布生命周期，并保留重复索引的重抽与接受顺序。
- 声明上下文：此定义组留在 `detail` 命名空间，依赖前置包含中的标准容器/分布类型和既有抽样阈值常量。`Selection` 特化持有并复用区间分布；`Draw` 特化在单次抽取中通过 `RandInt` 取索引。两个策略类及其成员声明、内联实现一并共享。
- 对应内核：`SampleRandomAccess` 完整函数体来源于 C++23 原始 2748–2804 行和 C++17 原始 2830–2886 行，片段为 `common/sampling/sample_random_access_body.inc`；`SampleReservoir` 完整函数体来源于 2809–2835 行和 2891–2917 行，片段为 `common/sampling/sample_reservoir_body.inc`。容器抽样的数量转换和位图分支分别维护在 `common/sampling/sample_container_count.inc`、`common/sampling/sample_container_bitmap.inc`，直接装配到两标准公开入口。各入口读取一次容器边界，默认入口在空范围返回后取得引擎，后续复用公开迭代器路径。随机访问迭代器及容器入口共同采用抽样内联策略，使边界和策略选择保留在调用点。`common/sampling/sample_random_access_operations.inc` 维护 `CopySamplePopulation`、`SampleSparseIndices`、`SampleDenseIndices`、`SampleDenseIndicesInline` 和 `SampleDenseIndicesOperation`；操作内核持有完整复制、哈希去重和稠密索引遍历；完整复制与哈希去重保持独立调用边界。稠密遍历正文由 `SampleDenseIndicesInline` 维护，分派入口使完整 64 位引擎在调用点展开，其他引擎经 `SampleDenseIndicesOperation` 保持独立调用边界。完整复制对可平凡复制的元素和原生指针、标准 `vector` 迭代器使用范围构造；其他来源保持预留容量后的索引复制。单元素完整复制在适配层直接完成。稠密内核按公开入口校验后的请求数量构造索引与结果；位图路径在调用点展开；`DrawSampleDistribution` 与 `DrawFullRangeSampleDistribution` 维护区间映射的内联策略，在位图和蓄水池路径中，对覆盖分布整数类型完整范围的引擎局部展开标准库调用。`RandPermutation` 的完整函数体来源于 2968–2980 行和 3035–3047 行，片段为 `common/sampling/rand_permutation_body.inc`。
- 声明上下文：抽样内核的模板参数、迭代器/哨兵、引擎获取器和公开 `RandSample` 适配声明仍在各标准根模板中；共同片段位于原有 `detail` 作用域及公开函数体位置。
- 测试契约：`tests/common/sampling_contracts.hpp` 覆盖请求尺寸与空输入边界、元素复制要求、随机访问和单遍路径、异常时迭代进度及引擎状态；`tests/common/sampling_observations.hpp` 记录受控引擎调用、抽样顺序、容器访问和源迭代进度，用于跨版本行为比较。

### 安全擦除后端

`detail::SecureWipe` 与 `detail::ScopedWiper` 继续由两标准来源在相同作用域展开。`common/security/secure_wipe_portable.inc` 维护 `SecureWipeCompilerBarrier` 与 `SecureWipePortable`；`common/security/secure_wipe_definition.inc` 维护 `SecureWipeBackend`、平台后端选择、`SecureWipeWithSelectedBackend`、后端名称和统一擦除入口。两份 preamble 负责平台头文件可用性及 Windows 头文件包含顺序。

后端宏改变 inline 定义，生产程序的所有翻译单元、静态库和预编译头需采用同一配置。CMake 将 `RANDX_USE_PORTABLE_SECURE_WIPE` 或 Apple opt-in 所需定义传播到全部 RandX INTERFACE 目标。双标准能力程序位于 `tests/security/`，分别编译直接包含与系统头预包含的翻译单元，并核对 selected backend 和 ChaCha20 移动生命周期。

## 实施验收

整数分布的候选类型政策位于 `common/distributions/integer_distribution_traits.inc`，两标准便捷接口分别装配 Concepts 与 SFINAE。内置流定位的材料位于 `common/engines/stream_jump_powers.inc`，应用内核位于 `stream_jump_apply.inc`；`tools/generate_stream_jump_powers.py` 从引擎转移和原始跳跃多项式独立推导材料，并验证每个状态基向量。C++23 现代特性与 C++17 引擎实现只承担公开声明和跳跃能力适配。

共同来源迁移的行为比较基点为 `85b7de2`。本节以下记录该批次的验证结果。该次迁移验收的生成产物为 C++23 150,454 字节、4,244 行，C++17 151,512 字节、4,203 行；146 个公共片段由两目标引用，162 个 `.inc` 均可达。生成检查与逐行来源映射通过，熵源模块的测试和 CI 验收范围见[熵源失败测试验收结果](熵源失败测试验收结果.md)。

- 生成器 17 项与真实来源映射 3 项单测通过，覆盖冲突写入前诊断、POSIX 路径、完整逐行映射、声明与正文双向定位，以及来源可达性和共同归属；`--check` 与 CMake 显式维护检查通过。维护选项关闭时不探测生成器 Python、不注册生成目标。
- GCC 16.1 的 CMake Release 构建及 5 项 CTest 通过，包含两标准完整测试、固定随机顺序测试和契约注册核对；六个示例及两个构建树 `find_package` 消费目标构建通过。
- MSVC 19.51 的 C++17/C++20/C++23 preview Debug/Release，以及 Clang 22.1.3 + MinGW GCC 16.1 libstdc++ 的 C++17/C++20/C++23 Release 矩阵通过；所有可执行文件默认和固定随机顺序运行均成功。
