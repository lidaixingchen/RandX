# 抽样与洗牌编译器属性实测

测量日期：2026-10-04。参考提交为 `7ceecebb0e3e50402e4a5fda6d3f16ff72240254`。实验只改变独立快照中的编译器策略；抽样算法、分布生命周期、基准正文和门禁策略保持既定实现。当前交付的策略与组合对照见[编译器属性收敛验收](编译器属性收敛验收.md)。

## 判断与适用范围

本轮建立了 GCC 16 上的属性贡献证据，不能据此把所有属性视为通用最佳实践。参考配置通过 GCC 14 的完整门禁。普通稠密内联在 GCC 16 局部消费者中更快，在 GCC 14 C++17 集成对照中存在已确认回归；相关证据见[性能策略评估](整数生成性能策略评估.md)。当前洗牌入口采用普通 `inline` 直接调用标准库，稠密请求使用普通上界表达；实际代价与验收范围见收敛验收。

下面的变化均表示**移除指定策略后，相对于参考实现的 CPU 时间变化**；正值表示移除后更慢。策略组同时覆盖的函数在因素定义中明确列出，组结果不能证明其中每一个成员都具有相同贡献。洗牌组合属性另外分解为独立属性对照。

## 环境与方法

Windows 11、MinGW GCC 16.1.0、libstdc++ 16、Google Benchmark 1.8.5；双边均使用 `-O3 -DNDEBUG -falign-functions=64 -falign-loops=64`，分别编译 C++17 和 C++23。仅实验子进程绑定可用亲和性掩码的最高一位（本机 CPU 15）并使用高于普通的进程优先级，保持两边相同；没有改变系统调频、SMT、ASLR 或正式门禁。

九组策略对照每组单独编译参考与变体：完整范围分布 `flatten`、四个公开随机访问／容器入口的强制内联、随机访问与蓄水池内核的强制内联、位图内核、三个分布包装、洗牌公开入口组合属性、洗牌内部包装组合属性、线性小样本辅助函数边界、稠密请求上界假设。洗牌额外四组分别移除公开／内部边界的 `always_inline` 或 `flatten`，保留另一个属性。

有效计时程序复用当前 `benchmark_gbench.cpp` 的抽样正文，并增加 `mt19937_64` 注册和两个默认洗牌规模；每个配置注册 326 项，用过滤器选择对应因素的用例。覆盖默认引擎、Xoshiro128、Xoshiro256、`mt19937_64`，随机访问容器、迭代器和单遍蓄水池，以及空请求、小样本、位图和稠密请求。抽样总体取 256 和 1,000,000，洗牌总体取 256 和 65,536。

每轮通过可写局部变量观察结果长度和存储指针，非空结果提交内存写入；请求在计时前观察一次，析构包含在每轮内。测量参数从现有策略读取：初测 5 轮、每项至少 0.1 秒；确认 6 轮、每项至少 1 秒。参考与变体按轮次均衡交替先后顺序，分别取各自轮次中位数后计算变化率。

九组策略初测共 272 个双标准比较项，确认覆盖 171 项，两个计数均已包含百万元素蓄水池补测的 24 项。主实验为 248 项初测、147 项确认；确认集合由初测 CPU 变化绝对值超过 25% 的项目，加上对应 Xoshiro256 和默认引擎代表项构成，其余 Xoshiro128／`mt19937_64` 项只有初测结果。百万元素蓄水池补测覆盖分布 `flatten`、分布包装和抽样内核三组策略，四种引擎全部执行六轮延长确认。四组洗牌属性分解均确认两个规模。全部实验共保存 704 次测量进程、5124 条原始记录，保留 CPU 与实际时间两个口径。初测、确认及各因素的用例集合分别保留，没有合并为完整基准门禁。

九组策略的 20 个功能配置，以及洗牌分解的 10 个功能配置，固定种子下完整输出和最终引擎状态均与参考逐字节相同，每个配置为 2,071,392 字节。该检查覆盖 66 个抽样／洗牌组合，总体规模为 256 和 65,536；百万元素计时用例不在此固定种子检查集合中。该检查不包含计时，也不替代公开契约测试。

| --- | ---: | ---: | ---: |
| 完整范围分布 `flatten` | -19.37% 至 +3.90% | -0.60% 至 +9.35% | 13／20；14／20 |
| 公开抽样入口强制内联 | -3.82% 至 +18.56% | -4.45% 至 +16.43% | 17／24；18／24 |
| 随机访问与蓄水池内核强制内联 | -3.42% 至 +25.54% | -4.26% 至 +11.34% | 17／28；16／28 |
| 位图内核强制内联 | -4.95% 至 +4.45% | +0.16% 至 +8.53% | 5／8；5／8 |
| 三个分布包装强制内联 | -3.94% 至 +2.95% | -1.86% 至 +4.42% | 13／20；13／20 |
| 洗牌公开入口组合属性 | +10.53% 至 +23.34% | +12.33% 至 +22.24% | 2／2；2／2 |
| 洗牌内部包装组合属性 | +0.70% 至 +1.04% | +0.00% 至 +1.04% | 2／2；2／2 |
| 线性小样本 `noinline` | -12.16% 至 +2.33% | -12.51% 至 +1.13% | 8／16；8／16 |
| 稠密请求上界假设 | -3.41% 至 +5.65% | -6.70% 至 +4.07% | 8／16；8／16 |

表中范围仅统计正样本确认项，项数则包含空范围和零请求；例如公开抽样入口的 17／18 项确认中，各有 12 项正样本用于范围计算。范围聚合描述该配置中的差异，不表示每个请求都相同，也不表示差异具有统计显著性。初测信号必须对照确认轮次与生成代码；短时 Windows CPU 计时存在量化，CPU 和实际时间结果均保留。

抽样内核组在 C++17 的显式 Xoshiro256 容器稠密请求（256／129）中，移除强制内联后 CPU 时间增加约 25.5%，实际时间增加约 25.9%；这支持当前组策略在该调用现场有贡献，但不能将组结果归因给每个成员。公开入口组的正样本也存在耗时增加，尚不支持整组直接移除。

完整范围分布 `flatten`、分布包装和位图内核的独立对照，没有呈现跨标准、跨用例一致的保留收益。完整范围分布在 C++17 的部分大请求中，移除后的确认中位数较低；个别大请求轮次离散明显，不能据此认定稳定收益。百万元素蓄水池补测变化接近零。因此，这些属性需要按调用现场继续验证，不能作为统一优化准则。

线性小样本边界和稠密上界假设的对照也未建立稳定的独立保留收益。上界前提的正确性与属性的性能贡献是两个问题；本轮只对满足既定公开契约的调用测量性能。当前上界表达的 GCC 14 集成对照及实际性能代价见收敛验收；线性小样本边界仍保持现有配置。

## 洗牌属性分解

| 切换为普通内联或移除的策略 | C++17 正样本确认变化 | C++23 正样本确认变化 | 确认／初测项数（17；23） |
| --- | ---: | ---: | ---: |
| 公开入口 `always_inline` | +12.07% 至 +21.56% | +11.94% 至 +23.56% | 2／2；2／2 |
| 公开入口 `flatten` | -0.02% 至 +0.12% | +0.00% 至 +0.12% | 2／2；2／2 |
| 内部包装 `always_inline` | -1.18% 至 -0.56% | -0.55% 至 +0.00% | 2／2；2／2 |
| 内部包装 `flatten` | -1.00% 至 +0.08% | +0.54% 至 +0.68% | 2／2；2／2 |

移除公开入口组合属性或仅移除其 `always_inline` 后，基准从展开后的洗牌循环变为每轮调用独立 `RandShuffle`；该函数内部的分布计算仍展开，没有新增逐次分布调用。仅移除公开入口 `flatten`、内部包装 `always_inline` 或内部包装 `flatten` 时，两标准代表洗牌函数的规范化指令与参考相同。本调用现场显示公开入口强制内联具有性能贡献；另外三项在另一层属性保留的条件下未显示独立代码生成贡献，不能据此推导两层属性同时移除的结果。当前配置采用普通入口直接调用标准库，本地约 79%–95% 的耗时增加及对应生成代码见收敛验收。规范化只消除符号地址及 RIP 相对位置差异，完整代表汇编与摘要同时保留；指令数量和调用目标不能单独换算成吞吐成本。

## 交付与下一步

当前生产提交的[CI](https://github.com/lidaixingchen/RandX/actions/runs/37152235610)为 19／19 通过，[Docs](https://github.com/lidaixingchen/RandX/actions/runs/37152235596)通过，[Benchmark](https://github.com/lidaixingchen/RandX/actions/runs/37152235620)四组共比较 641 项，新增、缺失和回归项均为零。基线为 `ec7cdb8b64dbbe213f23c97e0520a7cac991e53d`，各组在当次 runner 重建双边程序，沿用既定测量、确认和 25% 容差。

GCC 16 上未观察到独立收益的属性进入后续收敛候选，须用 GCC 14 当前完整调用现场重新做属性对照并通过集成门禁后再采用。功能 CI 的 Clang／MSVC 结果证明对应功能配置兼容；本轮没有测量它们的属性性能，也没有测量 ChaCha20、完整复制及哈希边界。固定种子检查未覆盖任意引擎、分配器故障或所有优化等级。
