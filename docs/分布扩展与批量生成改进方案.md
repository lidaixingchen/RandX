# 分布扩展与批量生成改进方案

日期：2026-10-04。状态：设计完成，待实施。C++17 同步策略：同步。破坏性：否，新增公开接口。

## 1. 目标与交付范围

新增 `RandDistribution` 和 `RandGenerateN`，为调用方持有的分布对象提供统一的单次采样与批量输出入口。两者均支持线程局部默认引擎及显式引擎，交付到现有 `RandX.hpp`、`RandX_Cpp17.hpp` 独立头文件。

主要收益是保留分布内部状态、复用参数预处理，并通过输出迭代器覆盖现有范围填充、序列容器追加、关联容器插入及自定义存储写入。分布、引擎和输出目标的所有权均由调用方明确持有。

容器工厂和配置门面作为后续需求观察项，暂缓排期。语言标准继续采用 C++17 与 C++23。既有具名分布、`RandFill`、`RandVector`、播种、安全随机和并行流接口保持原有契约；本项交付为新增能力。

本方案按三个层次验收：公开状态与异常契约、双版本接口及序列一致性、相同工作负载下的性能。实施完成前，本文中的接口、文件及检查均表示交付要求。

## 2. 现状与设计依据

### 2.1 当前可复用基础

- 两版本普通采样接口已有 `Engine&` 重载，`DefaultEngine()` 返回当前线程的 `Xoshiro256StarStar&`。
- `RandWeighted(std::discrete_distribution<IntType>&)` 已采用预构建分布对象引用，显式引擎重载直接调用 `dist(engine)`。新增入口推广这一使用方式。
- `RandNormal` 等具名分布接口按次创建标准库分布对象。它们继续承担现有参数校验和单次便捷采样契约。
- `RandFill` 以边界迭代器填充数值范围，可用于 `std::array`；`RandVector` 直接返回数值 vector。按数量向插入迭代器写入的通用分布入口需要新增。

维护来源和测试组织分别遵循[共同源码迁移清单](共同源码迁移清单.md)、[共享契约测试迁移清单](共享契约测试迁移清单.md)及[开发与验证](开发与验证.md)。

### 2.2 选择对象引用与输出迭代器

分布对象引用同时表达参数、缓存和生命周期。直接调用 `dist(engine)` 作为行为参照，可以精确验证新接口是否保留输出及随机消耗。标准分布允许内部状态，并通过 `reset()` 表达状态重置。[标准分布要求](https://eel.is/c++draft/rand.req.dist)

输出迭代器表达写入位置及写入方式。调用方可以传入原生指针、可写容器迭代器、`std::back_inserter`、`std::inserter` 或自定义输出迭代器。批量算法固定执行请求数量的生成与写入，返回推进后的迭代器；这一模型与标准生成算法一致。[标准生成算法](https://eel.is/c++draft/alg.generate)

分布构造在调用处显式完成。单次和批量接口均接收同一种对象引用，调用方可以在不同批次之间继续使用同一分布和引擎。

## 3. 公开接口

以下声明展示公开签名；实际实现附加第 4 节规定的 Concepts／SFINAE 约束。

```cpp
template <class Distribution>
[[nodiscard]] inline typename Distribution::result_type
RandDistribution(Distribution& dist);

template <class Engine, class Distribution>
[[nodiscard]] inline typename Distribution::result_type
RandDistribution(Engine& engine, Distribution& dist);

template <class Out, class Distribution>
inline Out RandGenerateN(Out out, std::size_t count, Distribution& dist);

template <class Engine, class Out, class Distribution>
inline Out RandGenerateN(
    Engine& engine, Out out, std::size_t count, Distribution& dist);
```

显式引擎始终为首个参数，延续现有 API 的调用习惯。批量入口的输出位置和数量在分布对象前，便于按 `输出位置、数量、生成器` 理解调用。批量返回迭代器可用于后续写入；调用方也可忽略返回值，因此该接口采用普通 `inline`。四个入口保留异常传播，采用普通异常规格。

### 3.1 单次采样

显式入口等价于一次 `dist(engine)`，按值返回 `Distribution::result_type`。默认入口获取当前线程的默认引擎后调用显式入口。

引擎与分布均通过引用使用；接口不复制、移动、重新构造或重置它们。分布可以不可复制，只要满足类型准入条件。分布参数检查、采样数学性质及引擎读取次数由所传分布负责。

### 3.2 批量输出

显式入口按下列顺序执行每次输出：

1. 调用一次 `dist(engine)`，取得一个样本。
2. 通过当前输出迭代器赋值。
3. 对输出迭代器执行一次前置递增。

成功完成时，执行恰好 `count` 次分布调用、写入及递增，返回推进后的迭代器。循环采用剩余次数递减控制，不对 `count` 加一；循环、调用顺序与对象引用正文在两版本之间共同维护。

默认入口在 `count == 0` 时直接返回传入的迭代器。正数量请求获取一次默认引擎，再执行显式入口。显式入口的零数量路径同样直接返回。

零数量请求不调用分布、引擎、迭代器解引用或递增，也不检查分布运行时参数。输出迭代器按值传入及返回时的对象构造行为仍由迭代器类型决定。

`count` 的类型为 `std::size_t`，表示非负生成次数。调用方从其他整数类型转换时，负责确认数量有效且可表示。对于有限可写范围，调用方须提供至少 `count` 个可写位置；接口通过数量控制执行，范围长度由调用方掌握。

### 3.3 容器语义

| 输出目标 | 写入方式 | 数量含义 |
| --- | --- | --- |
| 已有 array、原生数组、已定长 vector | 可写迭代器或指针 | 改写 count 个位置 |
| vector、deque、list | `std::back_inserter` | 追加 count 个元素 |
| multiset | `std::inserter` | 插入 count 个样本 |
| set | `std::inserter` | 尝试插入 count 个样本，重复值按容器规则合并 |
| 自定义容器或输出设备 | 自定义输出迭代器 | 执行 count 次生成和写入 |

插入拒绝重复值时继续下一次生成，生成总次数保持固定。容器最终大小遵循容器插入语义。预留容量、分配器、比较器和容器构造都在调用侧设置。

输出赋值遵循 C++ 赋值及转换规则。需要保留样本精度时，调用方使用匹配的元素类型；接口不额外执行数值转换检查。

## 4. 双版本类型准入

### 4.1 引擎与分布

引擎沿用现有 `detail::RandomEngine`／`detail::is_random_engine_v`。新增分布准入要求同时满足：

1. `Distribution` 为可变、非 volatile 的对象类型，参数绑定到左值。
2. 存在 `Distribution::result_type`，该类型为 cv 未修饰的算术值类型，包括 bool。
3. 对实际 `Engine&` 的表达式 `dist(engine)` 合法，其结果类型恰好为 `Distribution::result_type`。

标准库分布以及满足这些最小要求的自定义数值分布均可接入。接口只需要取样协议；`param_type`、流式序列化、比较和复制能力由分布自身按使用需求提供。

默认重载针对 `Xoshiro256StarStar&` 检查可调用性。显式重载针对实际传入引擎检查。临时分布、const／volatile 分布、缺少结果类型、返回 void／引用或返回类型不匹配的对象在重载选择阶段被排除。

表达式准入用于验证调用形态，运行时参数前置条件和模板函数体中的更具体要求仍由分布定义。分布对象应与其使用的引擎兼容。

### 4.2 输出迭代器

`Out` 按值传入并返回，要求可复制构造及可移动构造；对 `Out&` 的解引用赋值和前置递增表达式合法。赋值右侧类型为分布按值返回的 `result_type`。不依赖输出迭代器的 `value_type`，使插入迭代器及代理引用可以接入。

共同检测定义使用 C++17 可用的 `std::void_t`、`std::declval` 与类型特征。C++23 公开声明通过 `requires` 引用同一检测结果，C++17 通过 `enable_if_t` 引用同一检测结果。两版本约束对应实际使用的表达式，采用相同的支持集合。

类型探针须覆盖只提供所需前置递增的自定义输出迭代器、代理写入及标准插入迭代器，防止两版本因采用不同迭代器约束而产生准入差异。

## 5. 状态、异常与并发

### 5.1 状态及可复现性

- 同一分布对象在单次调用及不同批次之间保留全部内部状态，接口不调用 `reset()`。
- 重播种引擎只改变引擎状态。需要重现整段采样时，调用方恢复引擎，并按分布自身契约重置或恢复分布对象。
- `count` 表示分布调用次数。分布可能使用缓存或拒绝采样，一次分布调用实际消耗的引擎输出次数由该分布决定。
- 相同工具链、初始引擎、分布状态及输出操作下，新入口与直接调用参照保持样本、分布状态和最终引擎状态一致。
- 两版本在同一标准库及相同配置下执行相同的共同正文。跨标准库验证采用各自直接调用参照；分布算法允许实现差异。[标准分布算法规则](https://eel.is/c++draft/rand.dist.general)

### 5.2 异常进度

| 失败位置 | 可观察结果 |
| --- | --- |
| 分布调用，包括其内部引擎读取 | 当前输出位置尚未执行赋值；引擎和分布可能已改变 |
| 输出解引用或赋值 | 当前样本已生成；当前输出操作的影响由目标类型决定 |
| 输出递增 | 当前样本已经写入；迭代器进度由其递增操作决定 |
| 迭代器复制、移动或返回 | 已完成操作保留，构造异常向调用方传播 |

默认入口沿用默认引擎现有初始化与播种规则。接口原样传播分布及输出操作的异常，保留已经完成的输出及对象状态变化。它不保存恢复快照，也不追加恢复采样。对于一般用户分布和输出设备，异常保证取决于参与类型自身的保证；RandX 承诺停止执行后续步骤。

批量调用中发生异常时，通过外部记录或受控迭代器可观察进度；异常路径不返回迭代器。调用方需要事务性输出时，应在自己的临时存储和状态管理层完成提交。

### 5.3 线程与生命周期

默认引擎仍属于当前线程。分布对象及输出目标由调用方管理；线程局部引擎本身不使共享分布或共享容器自动获得并发安全性。并行任务各自持有引擎、分布和输出范围，或自行同步共享访问。分布对象需存活到同步调用结束。

## 6. 使用示例

示例中的固定参数使用具名常量，所有调用均使用同一份头文件与标准库。

```cpp
#include "RandX.hpp"
#include <array>
#include <cstddef>
#include <cstdint>
#include <iterator>
#include <random>
#include <set>
#include <vector>

constexpr std::uint64_t SimulationSeed = 20261004;
constexpr double SampleMean = 0.0;
constexpr double SampleStddev = 1.0;
constexpr std::size_t SampleCount = 32;

RandX::Xoshiro256StarStar engine{SimulationSeed};
std::normal_distribution<double> normal{SampleMean, SampleStddev};

const double first = RandX::RandDistribution(engine, normal);
const double second = RandX::RandDistribution(engine, normal);

std::vector<double> samples;
samples.reserve(SampleCount);
RandX::RandGenerateN(engine, std::back_inserter(samples), SampleCount, normal);

std::array<double, SampleCount> buffer{};
const auto finish = RandX::RandGenerateN(
    engine, buffer.begin(), buffer.size(), normal);

std::multiset<double> ordered;
RandX::RandGenerateN(
    engine, std::inserter(ordered, ordered.end()), SampleCount, normal);

std::normal_distribution<double> threadNormal{SampleMean, SampleStddev};
const double threadSample = RandX::RandDistribution(threadNormal);
```

C++17 示例改为包含 `RandX_Cpp17.hpp`，其余共同调用相同。示例中的连续调用共享 normal 状态；在独立任务或独立序列中创建各自的分布对象。

## 8. 测试设计

### 8.1 单次与分布状态

1. 使用同状态的两个引擎和两个分布，对比新入口与直接 `dist(engine)` 的逐次结果、最终引擎状态和可观察分布状态。
2. 覆盖整数、浮点、bool、标准 normal、预构建 discrete 及自定义数值分布。包含 32 位、64 位和标准库引擎。
3. 使用不可复制的受控缓存分布：第一次调用读取引擎并保存第二个样本，第二次调用返回缓存；确认入口访问的是原对象、缓存跨调用保留且不额外读取引擎。
4. 用标准 normal 对比直接调用，避免预设某个标准库的缓存实现或固定引擎读取次数。
5. 验证仅重播种引擎、同时恢复引擎与分布时的不同状态结果，测试自行恢复默认引擎，适配固定顺序重排。

### 8.2 批量、类型与容器

1. 零数量、单样本及多个样本的生成次数、写入次数、递增次数和返回位置。
2. 同一对象一次生成完整批次，与分拆成连续批次具有相同结果和最终状态；单次接口与批量接口交替使用时同样保持状态连续。
3. 原生数组、array、已定长 vector、vector 追加、list 追加、multiset 和 set 插入。以固定重复样本证明 set 最终大小可以小于生成次数且分布调用次数保持固定。
4. 标准插入迭代器、代理引用及只提供所需操作的自定义输出迭代器。
5. 编译期调用检测：合法分布与输出类型参与重载；临时或 cv 修饰分布、结果类型缺失／不匹配、非法引擎及只读输出类型被排除。两版本运行同一组静态断言。
6. 使用计数分布和计数引擎区分分布调用次数与底层引擎消耗，不把两者绑定为同一个数量。

### 8.3 异常与默认引擎获取

1. 受控分布在指定调用阶段抛出异常，核对已完成前缀、当前位置未赋值、对象状态及后续操作停止。
2. 分别在输出解引用、赋值和递增阶段抛出异常，核对第 5.2 节规定的执行顺序与进度；使用异常类型标记确认原异常传播。
3. 在 `CreateDefaultEngine` 的共同定义片段中，使用既有 `RANDX_ENABLE_ENTROPY_TEST_HOOKS` 配置声明 detail 线程局部构造尝试计数，并在执行播种前递增。生产配置完全排除该观测定义与递增。独立 hook 目标的新线程先执行零数量请求，计数须保持零；随后执行正数量请求，计数变为一次，再次请求保持一次。观测构造边界，不依赖硬件熵源是否使 OS 读取短路。
4. 正数量默认调用与显式默认引擎参照结果一致，生产目标验证输出和状态；hook 目标验证第 3 项的首次获取及后续复用。每个目标全部翻译单元使用一致宏配置，跨翻译单元读取同一线程计数，沿用既有桥接文件及 fixture 声明。
5. 生产配置与熵源 hook 配置分别登记测试结果，hook 宏仍只属于独立测试目标。

### 8.4 双版本及既有契约

新套件由两标准共同入口装配，纳入固定顺序重排和公共注册核对。parity 增加受控缓存分布、标准分布、连续分批与最终引擎状态；同机同工具链进行两版本比较。异常进度另由共同契约验证。

既有公开契约全部继续通过，尤其是 `RandNormal`、`RandWeighted`、`RandFill`、`RandVector` 和默认引擎序列。新入口复用调用方分布算法，主要证明转发与状态透明性；新增数学采样算法时按对应算法独立设计数值和统计验收。

## 9. 性能验证

新增 `benchmark_gbench_distribution_generation_cpp17` 和 `benchmark_gbench_distribution_generation_cpp23`，共用 `benchmarks/distribution_generation_benchmarks.cpp`，分别链接对应标准的 INTERFACE 目标。

基准场景包括显式引擎和默认引擎的单次采样、连续批次生成，以及预分配数组和容器插入。批量规模以 `EmptyBatchCount`、`SingleBatchCount`、`SmallBatchCount`、`MediumBatchCount`、`LargeBatchCount` 命名，取值分别为 0、1、32、1024、65536，用于观察固定入口成本、缓存跨批次使用和持续生成吞吐。基准的具体种子和分布参数同样使用具名常量。

主要参照为同样复用分布对象的直接调用循环。成对场景使用相同初始状态、生成次数、输出操作、容器分配与析构边界，防止把缓存生命周期差异误认为入口开销。另列逐次构造分布的测量，以说明对象复用的场景收益；该场景单独报告随机消耗和行为条件。

首次构造分布、首次初始化默认引擎与稳态吞吐分别计时。通过 Google Benchmark 的结果观察与内存屏障保留真实写入，记录分布调用及引擎读取计数。编译器、标准库、CPU、优化模式和原始结果随报告归档。出现稳定差距时，再用内联诊断及机器码定位调用边界。

既有四组回归门禁继续使用 `tools/benchmark_policy.json` 与 `tools/benchmark_gate.py`。新增接口相对直接调用的测量采用策略中 general 组的轮数、计时和容差，读取同一策略生成测量参数；显著超出容差的成对差距须定位并修正。新观察目标单独归档，实施时在 Benchmark 工作流接入构建、双版本运行与结果归档；新接口没有历史基线，首次报告注明这一事实。分布复用收益按实际工具链报告。
