# 分布复用与标准库批量生成方案

日期：2026-10-04。状态：使用材料交付与需求观察。C++17 同步策略：同步。交付范围：示例、文档与示例构建运行接线。

## 1. 目标与近期交付

为重复采样和批量输出提供可直接使用的双版本材料：调用方持有分布对象，通过 `dist(engine)` 单次采样，通过 `std::generate_n` 配合引用捕获批量生成。

近期交付覆盖显式引擎、线程局部默认引擎、连续分批、已有范围填充、序列追加、关联容器插入，以及 `RandBeta`、`RandTriangular` 等具名函数与标准算法的组合。分布、引擎和输出目标的所有权及生命周期由调用方管理。

公共接口扩展属于需求观察项。排期依据真实调用场景、标准库组合的使用成本和长期维护成本；具名分布及现有容器接口继续按各自契约使用。

## 2. 引入必要性与现有能力

### 2.1 分布对象复用

`RandNormal` 等具名便捷函数按次构造分布。对于重复使用相同参数的场景，调用方持有分布对象能够保留缓存，并复用分布构造时完成的参数预处理。实际收益取决于分布、标准库和工作负载。

两版本的 RandX 引擎可直接用于标准库分布。`DefaultEngine()` 返回当前线程的 `Xoshiro256StarStar&`；预构建 `RandWeighted` 重载也已支持调用方持有的 `std::discrete_distribution`。这些能力已经提供了对象复用所需的引擎接入方式。

标准分布允许内部状态，`reset()` 用于清除对先前引擎输出的依赖。[标准分布要求](https://eel.is/c++draft/rand.req.dist)

### 2.2 按数量输出

`std::generate_n` 接收输出位置、数量和生成器。生成器按引用捕获引擎及分布，就能在算法复制生成器时继续使用原对象，也能接入不可复制的分布。成功完成时，算法执行请求数量的生成和赋值，返回推进后的迭代器。[标准生成算法](https://eel.is/c++draft/alg.generate)

| 使用需求 | 当前推荐方式 | 所需调用侧管理 |
| --- | --- | --- |
| 标准分布单次采样与缓存复用 | `dist(engine)` | 分布构造、参数与生命周期 |
| 已有 array、数组或定长 vector | `std::generate_n` 与可写迭代器 | 可写范围容量 |
| vector、deque、list 追加 | `std::generate_n` 与 `std::back_inserter` | 容器容量和分配器 |
| set、multiset 插入 | `std::generate_n` 与 `std::inserter` | 容器比较器及重复值规则 |
| RandX 具名分布批量采样 | 在生成器中调用相应函数 | 函数参数和输出目标 |
| 独立随机序列 | 各自持有引擎及分布对象 | 初始状态及任务边界 |

标准库组合已经覆盖这些功能。公共封装的增量价值应通过统一调用约定、可诊断性或重复适配成本来证明；对象复用的收益由分布生命周期产生。

## 3. 使用方式

### 3.1 显式引擎与引用捕获

```cpp
#include "RandX.hpp"
#include <algorithm>
#include <cstddef>
#include <cstdint>
#include <iterator>
#include <random>
#include <vector>

constexpr std::uint64_t SimulationSeed = 20261004;
constexpr double SampleMean = 0.0;
constexpr double SampleStddev = 1.0;
constexpr std::size_t SampleCount = 32;

RandX::Xoshiro256StarStar engine{SimulationSeed};
std::normal_distribution<double> normal{SampleMean, SampleStddev};
const double first = normal(engine);
const double second = normal(engine);
std::vector<double> samples;
samples.reserve(SampleCount);
std::generate_n(std::back_inserter(samples), SampleCount,
                [&normal, &engine]() { return normal(engine); });
```

C++17 包含 `RandX_Cpp17.hpp`，其余共同调用相同。连续单次调用及批次共享同一 normal 对象；生成器捕获引用，避免分布缓存停留在生成器的副本中。独立任务创建各自的对象。

### 3.2 默认引擎与零数量

```cpp
std::generate_n(out, count, [&normal]() {
    return normal(RandX::DefaultEngine());
});
```

零数量时算法不执行生成器，因此这段调用不会访问默认引擎。分布对象、输出迭代器和生成器的构造仍发生在调用前，参与类型的构造行为遵循各自规则。

需要在整个批次复用一次取得的默认引擎引用时，先确认数量为正，再调用 `DefaultEngine()`，随后用引用捕获引擎和分布。默认引擎引用属于当前线程，使用范围遵循既有默认引擎生命周期契约。

### 3.3 具名分布函数

```cpp
std::generate_n(out, count, [&engine]() {
    return RandX::RandTriangular(
        engine, TriangularMinimum, TriangularPeak, TriangularMaximum);
});
```

这里的参数由调用方按场景定义为具名常量。`RandBeta` 等函数也按同一方式接入，生成器保留相应函数的参数检查和数值行为。普通生成器遵循标准算法的可调用要求。

完整可运行代码见[分布复用示例](../examples/distribution_generation.cpp)。

## 4. 参数、状态与输出规则

### 4.1 参数责任

调用方构造标准分布时须满足标准库前置条件。例如 `std::normal_distribution` 要求标准差为正；参数检查由所用分布定义。[正态分布前置条件](https://eel.is/c++draft/rand.dist.norm.normal)

RandX 具名函数仍按 [API 文档](API.md#统计分布17-种)执行参数检查及异常处理。标准分布直接调用与具名函数分别遵循各自的参数契约。

生成数量应为有效、可表示的整数；示例采用 `std::size_t`。有限输出范围至少提供请求数量的可写位置。写入遵循 C++ 赋值转换规则，需要保持样本精度时使用匹配的元素类型。

### 4.2 状态与可复现性

- 分布对象保留跨单次和跨批次的内部状态，调用方按自己的任务边界执行 `reset()`。
- 重播种引擎只改变引擎。要从起点重现序列，还须重置或重建分布；要从中途恢复序列，须恢复当时的引擎及分布状态。
- 生成数量表示分布或具名函数的调用次数。缓存和拒绝采样决定实际引擎读取次数，两种计数分别观察。
- 同一工具链、初始引擎和分布状态下，标准生成算法与直接循环应具有相同样本和最终状态。分布算法由标准库实现决定，跨工具链使用各自的直接调用参照。[标准分布算法规则](https://eel.is/c++draft/rand.dist.general)

### 4.3 容器、异常与并发

set 按自身规则合并重复样本，最终元素数量可以小于生成数量；批次按指定生成数量执行。multiset 保留重复值，序列插入迭代器执行追加。

标准算法使用符合其要求的输出迭代器和生成器。生成器、输出操作或迭代器操作抛出异常时，异常向调用方传播；已经发生的状态变化遵循参与类型的异常保证，异常路径没有返回的输出位置。事务性输出及状态提交由调用方自己的存储层完成。

线程局部引擎只隔离引擎状态。并行任务各自持有分布和输出目标，或者同步共享访问；引用捕获的对象须存活到同步算法调用结束。

### 6.2 公共接口需求评估

出现重复的真实使用场景时，收集调用代码、使用频率、所需分布和输出类型，以及标准库组合中必须重复维护的适配逻辑。评估单次与批量入口各自的价值，按证据确定扩展范围。

进入接口设计的条件是：调用方确实需要 RandX 层面的统一约定，且调用复杂度或适配维护成本足以承担新增 API 的文档、兼容性、双版本约束和长期验证成本。接口命名和签名在需求成立后的独立设计中确定。

若评估包含性能要求，应同时比较直接循环、`std::generate_n` 和拟议入口。三者使用相同对象状态、生成数量、输出操作和分配边界。逐次构造分布与复用分布分别报告；计数观测独立于吞吐计时，避免计数操作改变被测代码。

现有性能门禁仍以 `tools/benchmark_policy.json` 为权威。门禁容差用于判断回归；接口引入依据使用需求和测量结果。新观察项按获批范围接入构建、运行和归档。

### 6.3 后续接口设计的验证边界

公共封装若进入独立设计，应明确对象引用身份、实际调用表达式、参数责任、零数量、异常进度和生命周期。

输出约束须对应正文实际使用的完整表达式及值类别。例如采用 `*out = dist(engine)` 时，准入检测与正文一致，递增单独执行；代理引用和仅接收右值的输出类型须有实际函数体实例化证据。概念或 SFINAE 的签名探针只能验证声明中的表达式，分布模板函数体的具体要求通过真实调用验证。

生产实现的共同来源、生成产物和测试归属遵循[共同源码迁移清单](共同源码迁移清单.md)、[共享契约测试迁移清单](共享契约测试迁移清单.md)及[开发与验证](开发与验证.md)。双版本状态与随机消耗 parity、异常测试、默认引擎首次获取观测和性能接线按实际新增契约确定。
