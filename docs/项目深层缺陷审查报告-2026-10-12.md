## 数值行为

### F01：位置与尺度分布的中间溢出

位置：[Normal 显式入口](../src/header_sources/common/distributions/rand_normal_02_body.inc)、[Cauchy 显式入口](../src/header_sources/common/distributions/rand_cauchy_02_body.inc)、[ExtremeValue 显式入口](../src/header_sources/common/distributions/rand_extreme_value_02_body.inc)。默认入口也委托相应标准分布，本轮确定性运行使用显式引擎。

这些入口接受有限位置参数和正有限尺度，直接委托标准库。固定引擎输出选择的分位因子使尺度乘积先溢出，之后位置参数无法抵消已经产生的无穷。按同一分位计算的最终数学结果仍在 double 范围内。

令 `M = std::numeric_limits<double>::max()`：

| 调用参数 | 实际输出 | 同分位有限参考值 | 引擎输出数 |
| --- | --- | --- | --- |
| `RandNormal(engine, -M, M)` | `+inf` | GCC 约 `7.72004e307`；MSVC 约 `7.02821e307` | 2 |
| `RandCauchy(engine, M, M)` | `-inf` | 约 `-8.92745e307` | 1 |
| `RandExtremeValue(engine, M, M)` | `-inf` | GCC 约 `-4.36705e307`；MSVC 约 `-3.55610e306` | 1 |

两编译器的 C++17、C++23 均复现。标准库使用不同的分位变换与抽取顺序，探针对应各自算法冻结引擎输入，不能跨实现套用同一分位公式。这些案例不是结果本身超过类型范围的合理尾部。

验收要求：在有中间溢出风险的参数区间采用稳定的仿射计算，验证最终结果的可表示性；明确受影响路径的序列与消耗契约。复现源码为 `numeric/scale_affine_probe.cpp`、`numeric/msvc_scale_probe.cpp`。

### F02：小形状采样在尺度恢复前下溢

位置：[Gamma 显式入口](../src/header_sources/common/distributions/rand_gamma_02_body.inc)、[Weibull 显式入口](../src/header_sources/common/distributions/rand_weibull_02_body.inc)。

使用 `shape=1e-6`、`scale=M` 时，固定合法引擎序列使幂运算的单位尺度样本小于 double 最小可表示正数。标准库先将其舍入为零，再乘巨大尺度；真实缩放结果约为 `1e-127`，仍是普通可表示非零值。

| 入口 | 实际输出 | 有限参考值 | 引擎输出数 |
| --- | --- | --- | --- |
| `RandGamma(engine, 1e-6, M)` | 0 | GCC 约 `3.68851e-127`；MSVC 约 `5.53276e-127` | GCC 4；MSVC 3 |
| `RandWeibull(engine, 1e-6, M)` | 0 | 约 `5.53276e-127` | 1 |

四种编译器／标准组合均复现。MSVC 的 long double 与 double 精度相同，Gamma、Weibull、ExtremeValue 的有限参考值由 Miniconda Decimal 100 位计算核对；不使用同精度 C++ 中已经下溢或溢出的参考列。

验收要求：在小形状、大尺度组合下合并幂变换与尺度的对数，最后转换到返回类型；同时覆盖结果确实应舍入为零或无穷的尾部。该问题与前轮极大形状 Gamma 卡死分别维护。

### F03：小自由度稳定路径的覆盖边界

位置：[Student-t 路径判定](../src/header_sources/common/distributions/stable_gamma_log_sampling.inc)、[Fisher-F 路径判定](../src/header_sources/common/distributions/stable_gamma_log_sampling.inc)。

当前小自由度阈值约为 `2 / -log(smallest_positive)`。它没有覆盖阈值以上仍可能出现的 Gamma 幂变换下溢。自由度 `0.01` 在 double 中高于约 `0.00268658` 的阈值，两个公开入口均继续使用标准库路径。

主代理用固定 64 位引擎序列复现：

- Fisher-F 的两个同自由度 Gamma 样本使用完全相同的四次输入，生成的真实样本相等且为正；比值应为 1。两个中间 Gamma 值均被舍入为零，实际结果为 NaN，消耗 8 次输出。
- Student-t 的真实 Gamma 值虽小于 double 的最小正数，其平方根及最终商仍可表示。实际返回 `+inf`，对数域参考约 `6.48741e209`，消耗 6 次输出。

GCC 16.1 的 C++17、C++23 均得到相同结果。探针在 `primary/small_degrees.cpp`；其中四次 Gamma 输入为 `3/4、1/2、1/2、2^-7` 对应的 64 位原始值。Gamma 的提升形状样本为相同有限值，幂项约为 `exp(-970.4)`，足以解释下溢及最终比值。结论来自确定性变换，不依赖样本率差异。

对数域分区留下的多种子探针还在阈值上方观察到 Fisher-F NaN，主代理用上述短序列补足因果证据。MSVC 的同类控制序列得到有限结果且消耗不同，未据此确认 MSVC 的这项缺陷。Beta 与大自由度边界本轮未确认额外问题。

验收要求：稳定路径的选择应覆盖实际幂变换与后续开方、比值的数值风险，不能以单个典型指数补偿量作为安全分界。验证阈值两侧、三个浮点类型，以及结果可表示但中间 Gamma 不可表示的情形。

## 整数与泛型接口

### F04：字符整数填充与向量生成

位置：[默认 RandFill](../src/header_sources/common/convenience/rand_fill_02_body.inc)、[显式 RandFill](../src/header_sources/common/convenience/rand_fill_03_body.inc)、[显式 RandVector](../src/header_sources/common/convenience/rand_vector_02_body.inc)、[默认 RandVector](../src/header_sources/common/convenience/rand_vector_03_body.inc)。

这些入口允许非 bool 整数，却仅在 `sizeof(T) < sizeof(short)` 时转换到标准分布整数类型。Windows 上 char16_t 与 short 同宽，因而直接实例化 `uniform_int_distribution<char16_t>`。MSVC 按标准分布支持的整数类型列表触发 C2338。

最小调用：

```cpp
RandX::Xoshiro256StarStar engine{RandX::DefaultSeed};
std::array<char16_t, 2> output{};
RandX::RandFill(engine, output.begin(), output.end(), char16_t{0}, char16_t{15});
auto values = RandX::RandVector<char16_t>(engine, char16_t{0}, char16_t{15}, 3);
```

RandFill 和独立 RandVector 探针在 MSVC C++17、C++23 preview 均失败；GCC 两标准运行通过。char32_t、Windows 原生 wchar_t 也落入保留原类型的来源分支，属于同一受影响类型域；主代理独立编译复现固定使用 char16_t。

验收要求：让批量填充和向量生成采用与已修 RandInt 一致的标准整数分布类型映射，保留返回元素类型及边界。此项是前轮字符整数问题在其他入口中的遗漏。

### F05：RandIntCE 的宽区间窄化

位置：[两个重载及区间映射](../src/header_sources/cpp23/modern_features.inc)，关键窄化在第 84 行。

GCC 16.1 在 `-std=c++23` 和 `-std=gnu++23` 下均将 `unsigned __int128` 作为 `std::integral` 接受。两个重载均可调用，API 未规定 64 位上限。但区间跨度被转成 uint64_t，完整宽类型域分支也只取得一次 64 位输出。

已独立验证的最小案例：

```cpp
using Wide = unsigned __int128;
constexpr Wide upper = Wide{1} << std::numeric_limits<std::uint64_t>::digits;
constexpr Wide a = RandX::RandIntCE<Wide>(Wide{0}, upper);
constexpr Wide b = RandX::RandIntCE<Wide>(upper);
static_assert(a == 0 && b == 0);
```

这里跨度 `2^64` 被窄化为 0，区间长度变成 1，有界映射必然返回 0；因此固定下界不是偶然抽样结果。确认范围限 GCC 的扩展整数支持，不推及没有该类型的 MSVC。

验收要求：明确并在声明层表达编译期整数接口的位宽域。接口接受范围与公开文档须准确表达现有 64 位映射能力。

### F07：ranges RandFill 的 bool 能力声明

位置：[ranges 包装](../src/header_sources/cpp23/modern_features.inc)、[核心整数入口](../src/header_sources/cpp23/convenience.inc)。

`std::vector<bool>` 满足 `output_range<const bool&>`，包装的 requires 调用表达式也成立；实际调用 `RandX::ranges::RandFill(values, false, true)` 时，核心 RandFill 排除 bool，函数体无法匹配重载。

GCC C++23 的能力探针编译成功，实际调用探针编译失败。验收要求是让包装声明与转发的核心入口类型域一致。

### F08：洗牌的元素可置换性

位置：[C++17 RandShuffle](../src/header_sources/cpp17/convenience.inc)、[ShuffleCE](../src/header_sources/cpp23/modern_features.inc)、[ShuffledArray](../src/header_sources/cpp23/modern_features.inc)。

仅检查容器或迭代器的随机访问能力，并不保证解引用后的元素可交换。非 const 的 std::string_view 对象仍提供 const char 元素；const int 指针是随机访问迭代器，却不能写入。

GCC 已复现三种声明接受、函数体失败的调用：C++17 `RandShuffle(string_view)`、C++23 `ShuffleCE(const int*, const int*)`、`ShuffledArray(std::array<const int, N>)`。ShuffleCE 的独立 requires 探针可调用，实际调用在 iter_swap 处失败。C++23 的 ranges RandShuffle 已要求 permutable，不计入此项。

验收要求：在相应声明层表达实际交换／置换能力，保持合法可变元素的 constexpr 与运行时行为。

### F09：流读取的状态类型能力

位置：[C++23 SerializableEngine](../src/header_sources/cpp23/infrastructure.inc)、[C++17 trait](../src/header_sources/cpp17/engines_implementation.inc)、[读取正文](../src/header_sources/common/serialization/stream_read_body.inc)、[快照检查](../src/header_sources/common/engines/is_valid_snapshot_definition.inc)。

可索引状态和 serialize／deserialize 声明足以通过两个标准的类型约束。使用 `std::array<std::uint16_t, 2>` 的自定义引擎时，流读取却调用仅支持 uint32_t／uint64_t 数组的全零检查，实例化失败。

GCC 两标准的探针先用静态断言确认类型能力成立，再实例化流输入，均在 IsAllZero 处失败。内置引擎状态不受影响。验收要求是让读取约束准确表达当前支持的状态形式；支持的状态形态须与快照有效性检查一致。

### F10：deserialize 返回类型的双标准契约

位置：[C++17 trait](../src/header_sources/cpp17/engines_implementation.inc)、[C++23 concept](../src/header_sources/cpp23/infrastructure.inc)。

对于状态为 `std::array<std::uint32_t, 2>`、deserialize 返回 int 的自定义引擎，C++17 仅检测调用存在，允许流输入并忽略返回值；C++23 要求精确返回 void，拒绝同一接口。GCC C++17 编译运行成功，C++23 编译失败。

这是共同公开能力的兼容范围差异。验收要求是统一两标准的返回类型政策，并明确自定义引擎适配要求；内置引擎已返回 void。

### F11：公共抽样的复制能力域

位置：[C++23 输入入口](../src/header_sources/cpp23/convenience.inc)、[C++23 容器入口](../src/header_sources/cpp23/convenience.inc)、[C++17 输入入口](../src/header_sources/cpp17/convenience.inc)、[ranges 包装](../src/header_sources/cpp23/modern_features.inc)。

元素可以复制构造和复制赋值，但显式删除移动构造：

```cpp
struct CopyValue {
    int value;
    explicit CopyValue(int initial) : value(initial) {}
    CopyValue(const CopyValue&) = default;
    CopyValue(CopyValue&&) = delete;
    CopyValue& operator=(const CopyValue&) = default;
};
```

共同水库只要求从输入复制构造和赋值。C++17 的 trait 允许该类型，输入及容器抽样均编译运行成功；C++23 的 std::copy_constructible 额外要求右值构造，因此两条公共路径均被拒绝。同类型的 C++23 随机访问迭代器抽样和直接输入 RandElement 又可用。ranges 的 RandSample／RandElement 同样受该较强约束限制。

验收要求：按共同内核实际复制能力统一公共接口的双标准类型域，并核对包装层的元素政策。此项与已修的复制赋值遗漏不同。

## 工具与通知

### F06：PR 与回归 issue 的身份混淆

位置：[回归通知查重](../tools/benchmark_issue.cjs)。

GitHub Issues API 可以返回 issue 和 PR，可通过 pull_request 字段区分。[GitHub 官方文档](https://docs.github.com/en/rest/issues/issues#list-repository-issues)

现有查重仅按标签筛选后匹配标题前缀，没有区分两类条目。若开放 PR 带 benchmark 标签且标题以 `[Benchmark 回归]` 开头，它会被当作已有回归 issue，使通知跳过创建。

本地 API mock 返回该 PR 后，实际结果为 `created=false`、`duplicateNumber=41`、`createdIssueCount=0`。该条件可稳定重放；本轮未查询真实 issue 列表，不声称当前线上已经发生漏报。

验收要求：查重时准确匹配 issue 身份，并增加包含同前缀 PR 的通知契约。

### F12：超大整数的数据错误分类

位置：[测量值校验](../tools/compare_benchmark.py)、[策略数值转换](../tools/benchmark_gate.py)。

JSON 中 `cpu_time=10**1000` 能被 Python 解析为整数，但 math.isfinite 将其转成机器浮点时抛出 OverflowError。compare_benchmark CLI 实际退出码为 1；工具文档约定 1 表示性能回归，2 表示无效输入。

将策略 tolerance 换为同类整数，也会在 float 转换处抛出未捕获 OverflowError，而不是生成数据错误计划。主代理重放了比较 CLI 和 plan_run 路径；未重放完整 Actions 求值失败流程。

影响限于异常数值输入，普通 Google Benchmark 输出不会生成这种整数。验收要求是让数值表示范围异常进入已有的数据错误分类，保持退出码及结构化计划的语义。

- 生成输出覆盖配置、输出文件与目录祖先冲突属于人为矛盾的维护配置；当前两目标配置没有该冲突。工具未承诺通用事务写入，不计产品缺陷。
- 契约收集器对不可执行文件输出 traceback，仍失败退出且不生成清单；没有发现违反明确输出协议，归为诊断改进。
- 带 `-mrdrnd` 构建的目标要求相应 CPU 指令；非法 Reader 进度或未保存 errno 的信号处理器不属于生产熵适配器契约，未据此确认安全缺陷。
- 极端重尾的合理零／无穷、探针统计累计值溢出，以及 Poisson 上限附近尚未证明的尾部表示行为不计已确认问题。
