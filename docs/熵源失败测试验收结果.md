## 实现与契约

两个交付头文件从共同来源同步生成。`NativeOsEntropyReader` 解释平台返回值，`FillOsEntropy` 统一处理完整填充、短读、中断和失败。`RandomSeedWithSources` 管理普通播种的来源顺序及异常回退。公开接口、ChaCha20 状态提交顺序、重播种阈值和显式种子序列保持既有契约。

`RandomSeed` 独立编译，控制默认引擎初始化时平台调用与异常回退的展开规模。MinGW 和 MSVC 的两标准 Release 测试在该配置下各通过 10 项 CTest；远端矩阵同时验证调试、发布模式及跨标准序列。

独立 C++17/C++23 故障目标在全部翻译单元中启用私有 `RANDX_ENABLE_ENTROPY_TEST_HOOKS` 定义。普通测试和安装导出的 INTERFACE 目标使用生产配置。故障正文包含 10 个公共用例及 4 个内部用例，Windows 构建每次运行执行 375 个断言。

覆盖的失败场景包括零长度、全零有效材料、短读、中断、立即失败、部分填充后失败、安全接口异常传播、构造失败、手动和自动重播种失败与恢复、计数器耗尽状态、移出对象、跨阈值丢弃、存活数组擦除、普通播种来源短路与随机设备异常。正常流分别在缓存部分消费及恰好耗尽的位置验证重播种失败。跨翻译单元调用验证 hook 共享、嵌套和异常恢复；线程隔离测试在两个 hook 同时存活时通过 promise/future 顺序交错调用，分别核对脚本输出及消费记录。

## 验收命令

在仓库根目录使用对应 CMake/CTest 可执行文件。MinGW 两目录分别配置 `CMAKE_BUILD_TYPE=Debug` 和 `Release`；MSVC 使用 Visual Studio 18 2026 x64 生成器及 `--config` 选择模式。

```powershell
cmake --build build/entropy-tests-debug --parallel 4
ctest --test-dir build/entropy-tests-debug --output-on-failure
cmake --build build/entropy-tests-release --parallel 4
ctest --test-dir build/entropy-tests-release --output-on-failure
cmake --build build/entropy-tests-msvc --config Debug --parallel 4
ctest --test-dir build/entropy-tests-msvc -C Debug --output-on-failure
cmake --build build/entropy-tests-msvc --config Release --parallel 4
ctest --test-dir build/entropy-tests-msvc -C Release --output-on-failure

$env:PYTHONUTF8 = '1'
conda run --no-capture-output python -X utf8 -m unittest discover -s tools -p 'test_*.py'
conda run --no-capture-output python -X utf8 tools/generate_headers.py --check
conda run --no-capture-output python -X utf8 tools/generate_headers.py --map-dir build/entropy-validation/source-maps

g++ -std=c++20 -O2 -DNDEBUG -Wall -Wextra -I . -I third_party `
  -DRANDX_ENABLE_ENTROPY_TEST_HOOKS -DRANDX_ENTROPY_TEST_CPP17 `
  tests/entropy/test_entropy_cpp17.cpp tests/entropy/entropy_cross_translation_unit.cpp `
  -o build/entropy-validation/test_entropy_cpp20.exe -lbcrypt
```

预处理检查分别指定 `--standard c++17/c++20 --header RandX_Cpp17.hpp` 和 `--standard c++23 --header RandX.hpp`，例如：

```powershell

  --compiler g++ --standard c++23 --header RandX.hpp `
  --output build/entropy-validation/RandX-C++23.i
```

## CI 验收范围

GCC 14、Clang 18 和 MSVC 的 C++17/C++20/C++23 矩阵均运行故障测试的调试、发布和固定随机顺序配置，上传独立注册清单。macOS 15 的 Apple Clang 编译 C++17/C++23 故障目标，并通过普通安全测试验证真实 `SecRandomCopyBytes` 调用与 Security framework 链接。普通安全用例从共享安全测试正文构建生产配置的独立入口，由 `run-selected` 执行，从 XML 验证每个指定名称恰好运行一次且成功，核验汇总计数及退出码，缺项或失败时保留诊断。

指定套件比较同时核对公共及内部用例，要求每项恰好注册一次，识别缺失套件、重复项、跨标准差异及跨编译器或平台组差异。三标准组要求 C++20 清单；macOS 明确声明采用 C++17/C++23 标准对。

覆盖率作业分别采集生产和故障报告。原 80% 行覆盖率门槛应用于生产报告；故障报告单独列出熵函数的分支位置和执行次数。解析器支持 LCOV 的 `FN/FNDA` 及 `FNL/FNA` 记录，保留函数范围和别名，同一范围的分支只计一次。两报告的来源、函数范围、别名、行及分支结构一致时生成补充合并报告，原始报告继续保留。预处理文本及命令记录单独上传。
