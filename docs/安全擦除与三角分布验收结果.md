## 交付内容

共同擦除入口根据 SDK、声明环境和构建配置选择 Windows `SecureZeroMemory`、glibc `explicit_bzero`、Apple 显式启用的 `memset_s` 或共同兼容实现。兼容实现采用 volatile 字节写入和编译器屏障。零长度早返回；Apple 请求按 `RSIZE_MAX` 分块。CMake 的后端选项传播到生产 INTERFACE 目标；全部翻译单元及预编译头须使用一致配置。

`RandTriangular` 默认与显式引擎重载共享 `TriangularKernel<T>`。参数须有限、顺序正确且返回类型宽度可表示。非法及退化调用不获取默认引擎、不消耗随机数。有效非退化调用取得一次 `RandCanonical<T>`，采用独立右尾比例、端点／众数分段计算和近众数有理化插值，并固定接点两侧的输出边界，输出按 `[min,max)` 纠正。float 内部使用 double，其他类型保持原生精度。

三角分布公开、统计和内部数值正文分别归属 `tests/common/triangular_distribution_contracts.hpp`、`tests/common/triangular_statistical_contracts.hpp` 和 `tests/implementation/triangular_contracts.hpp`。完整测试入口与独立小目标复用相同正文。参考生成器使用标准库 Decimal/Fraction，无消费者依赖。

三角参考采用已转换到公开半开政策的目标类型结果。普通形状的预算为 6 份运算舍入、1 份输出量化、1 份参考舍入，共 8 ULP；宽度达到最小正规数的跨零区间使用同预算乘以返回类型 epsilon 的宽度归一化绝对误差；同号极端端点众数仍按局部 ULP 验收。跨零结果的相对条件数随结果趋零而增大，验收以宽度尺度为准。`u=0` 必须精确返回 min，次正规宽度按一个实际量化间距验收，相邻端点要求离散结果一致；有限性、半开边界与单调性独立检查。此预算用于已登记参考材料，API 不承诺任意参数均正确舍入。

## 优化擦除证据

当前已登记并完成机器码与变异确认的规则为 MinGW GCC 16.1.0／16.2.0、Windows x64 ABI。每个版本均覆盖 C++17／C++23 × Release／LTO × native／portable 共八组；每组构建基线及 16 个擦除删除变异，共 136 个最终链接产物。两个版本各自的八组基线通过，各 128 个变异均被同一检查器的对应检查项拒绝。

最终机器码逐项核对直接擦除 37 字节、正常守卫 43 字节、异常守卫 41 字节；ChaCha20 状态 48 字节、缓存 64 字节、generateBlock 两个独立栈临时数组各 64 字节、重播种种子 44 字节。核对移动源擦除在复制读取之后、移动赋值旧目标擦除在覆盖写入之前、重播种旧缓存擦除在新状态提交之后，以及正常和异常退出中的种子擦除。

已审阅的 C++23 Release 栈映射：generateBlock 的状态和工作数组分别为 `rsp+64` 与 `rsp+128`；重播种种子为 `rsp+32`。移动与析构探针以运行时对象指针为入口，缓存相对对象偏移为 48。具名数组位置来自最终产物的 DWARF CFA 栈位置，异常落地点来自 PE 的 GCC LSDA。原生路径识别实际 `rep stos` 零写，兼容路径核对逐字节、展开与索引循环的入口和完整范围。检查器逐路径追踪实际目标与覆盖字节，分别验证正常和异常退出；初始化负对照不计为消费后的擦除。

同一生产配置探针在新进程中首先执行非法和退化默认三角调用，再执行有效调用作为初始化正对照。检查各探针可达机器码：前两者无默认引擎初始化路径，有效调用保留该路径。擦除后不读取目标材料；生命周期检查不依赖销毁后存储读取。

完整证据位于 `build/secure-wipe-acceptance/report.json` 及其八组目录，含编译器信息、命令、执行日志、最终反汇编、PE 异常表、DWARF 调试信息和逐项 `audit.json`。128 个变异均由对应检查项明确拒绝。重放命令：

```powershell
conda run --no-capture-output python -X utf8 tools/check_secure_wipe_codegen.py --compiler g++ --disassembler objdump --standard both --optimization both --backend both --verify-mutations --output-dir build/secure-wipe-acceptance
```

退出码 0 为通过，1 为失败，2 为无法判定。其他编译器、ABI、版本、后端或无法识别的反汇编不能登记为通过。编译失败不构成检出擦除删除的证据。

GCC 16.2 的正式远端证据位于 `build/ci-37190948146-wipe/`，整体报告为 `pass`，136 项审计完成，128 项变异的 `detected` 均为 true。工作流归档 `secure-wipe-final-binary-evidence` 保留同样的命令、机器码、异常展开和逐项判定。报告采用 UTF-8，先完整保存再输出控制台诊断。

## 性能与 CI

新增两标准独立三角基准，覆盖 float／double、32／64 位引擎、对称、左右偏斜、两端点众数和退化路径，每标准 24 项。三个参数作为完整数组在计时前观察，结果使用可写局部变量防止计算被删除，JSON 记录每样本实际引擎消耗。基准与记录验收工具均核对消耗，测量错误和场景／重复集合缺失会导致工作流失败。

本机 MinGW GCC 16.1.0、`-O3 -DNDEBUG`、Google Benchmark 1.8.5，按现有 general 策略执行每项 0.5 秒、重复 5 次。两标准各 24 项及全部 120 条原始测量通过消耗核对：退化为零，32 位引擎生成 double 为两次，其余非退化场景为一次。非退化 CPU 中位数范围为 C++17 的 17.26–24.07 ns、C++23 的 18.14–26.68 ns。这是本机首次观测，暂无历史比较；不构成跨工具链性能结论。

配置采用 `BENCHMARK_ENABLE_WERROR=OFF`，以编译该依赖版本在当前 GCC 下的枚举警告。证据位于 `build/triangular-benchmark/`，包括 `compile_commands.json`、两标准原始 JSON、执行日志及 UTF-8 转换副本。Windows Google Benchmark 输出的主机名使用系统 ANSI 编码，验收工具读取 UTF-8 转换副本；数值记录保留原始值。
