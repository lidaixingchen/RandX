## 已确认问题

### D01：输入抽样计数溢出，导致异常与采样偏差

**位置：** [共同水库实现](../src/header_sources/common/sampling/sample_reservoir_body.inc)，第 8、18、20 行；[C++23 RandElement](../src/header_sources/cpp23/convenience.inc)，第 181—184、219—222 行；[C++17 RandElement](../src/header_sources/cpp17/convenience.inc)，第 217—221、259—264 行。

**触发：** 输入使用标准库提供的窄差值迭代器，范围包含 130 个整数，抽样数量为 1：

```cpp
using Narrow = std::istream_iterator<int, char, std::char_traits<char>, signed char>;
constexpr int InputCount = 130;
std::ostringstream text;
for (int index = 0; index < InputCount; ++index)
    text << index << ' ';
std::istringstream input{text.str()};
RandX::Xoshiro256StarStar engine{RandX::DefaultSeed};
auto sample = RandX::RandSample(engine, Narrow{input}, Narrow{}, static_cast<signed char>(1));
```

在 C++23 中，该标准迭代器通过 `std::input_iterator<Narrow>`。它逐项读取输入，不需要用差值表示整个流的长度。

**实测：** 四种编译器与标准组合均出现相同结果。对相同输入调用 `RandElement(engine, first, last)`，抛出 `RandInt: min > max`。使用种子 0—9999 调用 `RandSample`，窄差值迭代器抽中末尾两个元素 **0 次**；同输入、同种子的普通 `std::istream_iterator<int>` 抽中 **140 次**。正常概率为 `2/130`，1 万次的期望次数约为 154。

**原因：** 水库算法中的计数表示“已观察的元素数量”，实现却用 `iterator::difference_type` 保存。计数超过本机 `signed char` 最大值 127 后转为负数。`RandElement` 随后把负数作为闭区间上界，触发参数异常；`RandSample` 把它转成接近 `UINT64_MAX` 的上界，使末尾元素的替换概率骤降。统计结果用于展示影响，错误机制由计数类型和转换路径直接确定。更宽的有符号差值类型也存在相应的长度边界。

**修复要求：** 将输入遍历计数与请求数量、迭代器差值类型分开，使用与随机索引域一致的计数表示，并定义其容量边界。保持普通长度的抽样概率和随机消耗契约；增加窄差值标准输入迭代器的双标准回归，同时覆盖默认及显式引擎的 `RandElement`、`RandSample`。

### D02：大自由度 Student-t 退化为全零输出

**位置：** [默认引擎实现](../src/header_sources/common/distributions/rand_student_t_body.inc)，第 4—5 行；[显式引擎实现](../src/header_sources/common/distributions/rand_student_t_02_body.inc)，第 4—5 行。

**最小触发：**

```cpp
RandX::Xoshiro256StarStar engine{RandX::DefaultSeed};
constexpr double Degrees = 0x1p61;
const double value = RandX::RandStudentT(engine, Degrees);
```

自由度是正有限数，符合入口契约。Student-t 在自由度增大时趋近标准正态分布；其方差 `n/(n-2)` 在这里约为 1，不会趋于零。

**实测：** MSVC 的 C++17 与 C++23 均在 `double` 自由度 `2^61` 下产生 **4096/4096 个零**，样本二阶矩为 0；默认引擎入口结果相同。`float` 自由度 `2^32` 也产生全零；本机 MSVC 的 `long double` 与 `double` 使用相同精度，结果同样退化。自由度 10 的对照样本没有零，二阶矩约为 1.24458，接近理论值 1.25。GCC 对上述大自由度的 `double` 样本二阶矩约为 1.01875，没有全零退化。

**原因：** RandX 直接委托 `std::student_t_distribution<T>`。本机 MSVC 的 `<random>` 第 3865—3883 行使用：

```cpp
V1 * sqrt(n * (pow(R, -4 / n) - 1) / S)
```

当 `n` 很大时，指数结果与 1 的差远小于类型精度，`pow` 舍入到 1。紧接着减 1 得到零，最终把正常量级的随机结果压成零。直接数值缺陷位于本机 MSVC 标准库，RandX 的参数域暴露了这个兼容性问题。

**修复要求：** 为极端自由度提供稳定的等价采样公式。验证 float／double／long double 的完成性、分布量级、默认与显式引擎入口，以及常规参数的随机消耗。

### D03：大自由度 Fisher-F 返回 NaN

**位置：** [默认引擎实现](../src/header_sources/common/distributions/rand_fisher_f_body.inc)，第 4—5 行；[显式引擎实现](../src/header_sources/common/distributions/rand_fisher_f_02_body.inc)，第 4—5 行。

**最小触发：**

```cpp
RandX::Xoshiro256StarStar engine{RandX::DefaultSeed};
constexpr double Degrees = 0x1p768;
const double value = RandX::RandFisherF(engine, Degrees, Degrees);
```

两个自由度均为正有限数，通过参数校验。等大自由度下，Fisher-F 集中在 1 附近；均值 `n/(n-2)` 有限且约为 1。

**实测：** GCC 的 C++17、C++23 均返回 NaN，默认和显式引擎入口一致。按各浮点类型最大指数的四分之三构造自由度时，float、double、long double 都复现。`double` 案例显式引擎消耗 6 次输出后返回 NaN；MSVC 对相同参数返回 1。

**原因：** RandX 直接委托 `std::fisher_f_distribution<T>`。本机 libstdc++ 的 `bits/random.h` 第 3981 行计算：

```cpp
(gamma_x(engine) * n) / (gamma_y(engine) * m)
```

Gamma 样本分别约为 `m/2`、`n/2`，两个乘积均超过返回类型的有限范围。尽管理论比值约为 1，中间计算已经变成正无穷除正无穷，结果为 NaN。

**修复要求：** 使用经缩放的 Gamma 比值或对数域计算，使理论有限的比值保持有限。验证三个浮点类型、自由度比例不对称的案例，以及默认和显式引擎入口；同时覆盖小自由度下的尾部行为和常规参数随机消耗。

### D04：RandElement 输入路径遗漏复制赋值约束

**位置：** [C++23 迭代器入口](../src/header_sources/cpp23/convenience.inc)，第 172—186、210—224 行；[C++17 迭代器入口](../src/header_sources/cpp17/convenience.inc)，第 207—223、248—266 行；[C++23 ranges 包装](../src/header_sources/cpp23/modern_features.inc)，第 165—197 行。

**触发：** 元素能复制构造，但不能复制赋值：

```cpp
struct CopyOnly {
    CopyOnly() = default;
    CopyOnly(const CopyOnly&) = default;
    CopyOnly& operator=(const CopyOnly&) = delete;
};
std::list<CopyOnly> source(3);
RandX::Xoshiro256StarStar engine{RandX::DefaultSeed};
auto value = RandX::RandElement(engine, source.cbegin(), source.cend());
```

**实测：** GCC 和 MSVC 的两标准版本，默认及显式引擎入口均在 `selected = *first` 处编译失败。C++23 ranges 的默认及显式入口同样失败；该类型满足包装声明中的 `std::copy_constructible`，`requires` 调用表达式也通过。相同元素类型的 `std::array` 对照，在随机访问迭代器入口和 ranges 入口均可编译。

**原因：** 输入路径先复制构造选中元素，之后通过复制赋值更新。声明约束只检查迭代器类别；ranges 包装额外检查复制构造，仍遗漏更新所需的赋值能力。泛型调用方据此检测到接口可调用，实际实例化时却失败。

**修复要求：** 按实际分支补齐元素约束，保持随机访问路径对仅能复制构造元素的支持，并验证 `requires`／SFINAE 的可调用性。此问题属于 `RandElement`，与前轮已修复的 `RandSample` 复制赋值契约分别维护。

**文档同步：** [API 文档](API.md)第 217—220、336 行把输入迭代器入口描述为返回迭代器；当前实现返回元素值，应按随机访问路径和输入路径分别描述。[ranges 源码注释](../src/header_sources/cpp23/modern_features.inc)第 164 行存在相同表述。

### D05：MakeStreamEngine 遗漏返回对象的构造要求

**位置：** [共同建流实现](../src/header_sources/common/engines/stream_jump_apply.inc)，第 92—96 行；[C++23 StreamEngine 约束](../src/header_sources/cpp23/infrastructure.inc)，第 118—120 行。C++17 对应的 `HasStreamEngine` 同样只组合 jump 和种子列表构造能力。

**触发：** 自定义引擎可以从 `uint64_t` 种子构造，提供精确返回 void 的 `jump()`，但删除复制和移动构造：

```cpp
ImmovableEngine(const ImmovableEngine&) = delete;
ImmovableEngine(ImmovableEngine&&) = delete;
```

探针的随机生成与 jump 均委托 `Xoshiro256StarStar`，其 C++23 类型通过 `std::uniform_random_bit_generator` 和 `detail::StreamEngine`；C++17 通过 `detail::HasStreamEngine`。随后调用 `MakeStreamEngine<ImmovableEngine>(0, DefaultSeed)`。

**实测：** GCC 和 MSVC 的两标准版本均在共同实现的 `return engine` 处失败，诊断指向已删除的移动构造。

**原因：** 返回命名局部对象的复制消除属于允许执行的优化，函数仍须具有合法的返回构造路径。当前“完整能力”约束只检查种子构造与 jump，遗漏了这一要求。内置可移动引擎不受影响。

**修复要求：** 让两个标准的建流可调用性约束包含实际返回所需的构造能力，覆盖可移动、可复制和两者均删除的自定义引擎，保持内置引擎的 constexpr 建流与序列。

### D06：RandIntCE 接受 bool 后在函数体实例化失败

**位置：** [C++23 编译期整数接口](../src/header_sources/cpp23/modern_features.inc)，第 69—75、90—94 行。

**最小触发：**

```cpp
constexpr bool value = RandX::RandIntCE<bool>(false, true);
```

单参数 `RandIntCE<bool>(true)` 同样复现。

**实测：** GCC 和 MSVC 均编译失败。`std::integral<bool>` 为真，声明层面的调用表达式通过；函数体实例化 `std::make_unsigned_t<bool>` 时失败。

**原因：** `std::integral` 包含 bool，但函数体所用的无符号映射不支持 bool。该接口与已有普通整数生成入口的类型政策不一致。

**修复要求：** 明确编译期整数接口的类型域，并让两个重载约束一致。回归应验证 bool 的声明层面可调用性，同时保持普通整数和字符整数的 constexpr 结果与范围契约。

## 修复验收

### 最终实现

| 项目 | 交付行为 |
| --- | --- |
| D01 | 水库与单元素输入抽样使用独立 `uint64_t` 计数，实际读取超过计数容量时抛出 `length_error`。水库按实际输入增长；请求数量大但输入短时返回全部实际元素。单元素路径在差值类型可表示的范围内保留原随机映射，超出后使用完整计数域。 |
| D02 / D03 | 共同对数 Gamma 内核生成归一化样本。Student-t 用正态与归一化 Gamma 的对数商；Fisher-F 在共同尺度相减尾部补偿后计算归一化 Gamma 比值。大自由度和小形状风险区间走稳定路径，常规参数仍委托标准分布。float 使用 double 工作精度，double／long double 使用自身精度。 |
| D04 | 输入迭代器入口要求复制构造与复制赋值；ranges 按实际分支检查赋值能力。随机访问分支保留仅能复制构造的元素支持，输入分支支持显式删除移动构造但可复制的元素。文档区分迭代器返回与元素值返回。 |
| D05 | 两标准建流约束要求能够从引擎右值或左值构造返回对象。可移动类型保留命名返回值优化；显式删除移动构造但可复制的类型使用左值构造。 |
| D06 | 两个 `RandIntCE` 重载均在声明约束中排除 bool，普通整数及字符整数继续满足 constexpr 范围契约。 |

稳定分布保持合法参数域。极端尾部超过返回类型范围时，Student-t 可以返回带符号无穷，Fisher-F 可以上溢为正无穷或下溢为零。最小次正规自由度保留在尾部补偿尺度中；相邻补偿项的回归核对比值方向，防止有限差异在中间计算中丢失。上述风险参数的输出序列与随机消耗会改变；常规参数的输出和引擎状态保持原路径。
