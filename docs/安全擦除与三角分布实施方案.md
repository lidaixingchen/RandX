# 安全擦除与三角分布实施方案

日期：2026 年 10 月 4 日

代码基点：`3128c20`。状态：生产实现与验证工具已落地，完整验收进行中，实际结果见[验收记录](安全擦除与三角分布验收结果.md)。

## 1. 目标与实施顺序

本方案覆盖两项近期工作：强化 `detail::SecureWipe` 的平台实现与优化构建验证，新增 `RandTriangular` 三角分布。先完成安全擦除，再完成分布实现，共用源码生成、双版本契约测试、跨平台 CI 与性能门禁。

安全擦除的主要收益是为敏感数组的实际擦除建立平台契约与最终机器码证据。首先审计当前 volatile 循环在目标编译器的 Release／LTO 构建中的表现，再验证平台后端与兼容路径。

三角分布的主要收益是支持具有明确下界、众数和上界的模拟采样。算法与参数契约集中到一个内部模块，两个公开重载及两标准声明复用共同实现。测试从公开接口验证参数、引擎消耗与分布特征，并通过内部纯数值接口验证极端分位点。

公开引擎类型、现有随机序列、ChaCha20 重播种提交顺序、熵源失败语义和独立头文件交付形态维持既有契约。Zipf 分布、SIMD、流分配器和新随机类型层级另行设计。

## 3. 安全擦除契约与平台选择

### 3.1 接口与行为

`SecureWipe` 保持 `noexcept`，零长度立即返回，允许 `SecureWipe(nullptr, 0)`。非零长度要求传入有效可写存储，擦除恰好指定字节，保留邻接字节。无需分配内存、读取熵或抛异常。

`ScopedWiper`、ChaCha20 重播种、移动构造、移动赋值和析构中的擦除顺序保持当前行为。重播种仍在完整取得新材料后提交状态并擦除旧缓存，局部种子在正常退出和异常展开时均由守卫擦除。

### 3.2 选择规则

| 环境 | 原生路径与选择条件 | 兼容路径 |
| --- | --- | --- |
| Windows MSVC／MinGW | 库的 Windows SDK 包含分支取得声明后使用 `SecureZeroMemory`，保留 `NOMINMAX` 与 `<windows.h>`／`<bcrypt.h>` 顺序 | 未进入 SDK 包含分支或显式选择兼容后端时使用共同兼容实现 |
| glibc Linux | 包含 `<string.h>` 后，确认 glibc 版本至少为 2.25，且 `__USE_MISC` 表示头文件已暴露 `explicit_bzero` | 老版本、受限声明、其他 libc 或显式选择兼容后端时使用共同兼容实现 |
| Apple 平台 | 构建级启用 `RANDX_USE_APPLE_MEMSET_S`，统一预先开启扩展声明，提供 `RSIZE_MAX`，且 SDK 与部署目标满足可用版本 | 默认使用共同兼容实现；显式启用原生路径的构建必须满足其前提 |
| 其他环境 | 使用共同兼容实现 | 参与编译和优化构建验证 |

平台名或 `__has_include(<string.h>)` 不足以证明函数可用。选择条件必须反映声明可见性和部署版本；单头文件不能依赖仅在维护者 CMake 配置中生成的能力宏。Windows SDK 包含分支使用库自己的包含标记选择后端，其他包含顺序由独立消费样例验证。

glibc 版本检测放在已确认 `__GLIBC__` 及 `__GLIBC_PREREQ` 存在的预处理分支内，再调用 `__GLIBC_PREREQ(2, 25)`；函数式宏的存在性单独判断。声明条件读取系统头计算的 `__USE_MISC`，调用方通过编译选项在所有系统头之前设置 `_DEFAULT_SOURCE` 或 `_GNU_SOURCE`。库保持调用方的特性宏配置，不补写系统函数声明。

选择 `explicit_bzero` 会引入 glibc 2.25 的运行时符号要求。发布构建使用代表部署下限的 sysroot；需要选择兼容擦除后端时，在整个构建中启用 `RANDX_USE_PORTABLE_SECURE_WIPE`。该选项仅规定擦除后端，程序其他系统接口的部署约束仍按各自契约验证。

Apple 原生路径要求通过编译选项统一设置 `RANDX_USE_APPLE_MEMSET_S=1` 与 `__STDC_WANT_LIB_EXT1__=1`，早于任何系统头，包括预编译头。库显式包含 `<stdint.h>` 和 `<string.h>`，取得 `RSIZE_MAX`、`rsize_t`、`errno_t` 及 `memset_s` 声明。选择条件覆盖 macOS 10.9／iOS 7.0 的部署下限；其他 Apple 目标在其 SDK 可用性确认后登记。显式启用时，宏、上限或部署条件不足须产生清楚的编译诊断；声明本身由实际调用的编译检查确认。默认 Apple 路径由兼容实现提供完整契约。

`memset_s` 每块长度为剩余长度与 `RSIZE_MAX` 的较小值，同一块的目标容量与擦除长度相等，非零调用始终满足有效目标、正上限和长度约束。有效调用应返回零；对于已经返回的非零状态，使用兼容实现完成该块。完整擦除保证建立在有效调用及已验证的平台行为上，原生约束处理器的进程终止不属于可恢复返回状态。库保持调用方的约束处理器配置和 `noexcept` 接口。

兼容实现保留 volatile 写入，并在编译器支持时使用明确的编译器内存屏障。GCC／Clang 的屏障放在编译器适配层内；其他工具链使用其可用机制及实际审计结果。编译器屏障用于约束优化，不能替代防删除探针的实际证据。

来源依据：[Microsoft SecureZeroMemory](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/legacy/aa366877(v=vs.85))、[GNU 擦除文档](https://sourceware.org/glibc/manual/latest/html_node/Erasing-Sensitive-Data.html)、[glibc 声明条件](https://github.com/bminor/glibc/blob/master/string/string.h)与[符号版本](https://github.com/bminor/glibc/blob/master/string/Versions)、[Apple 头文件声明](https://github.com/apple-oss-distributions/Libc/blob/main/include/_string.h)。本项验证指定存储的擦除，不扩大为寄存器及编译器临时副本的全量清除保证。

### 3.3 生产配置与跨翻译单元契约

`RANDX_USE_PORTABLE_SECURE_WIPE=1` 在所有平台优先选择兼容实现；`RANDX_USE_APPLE_MEMSET_S=1` 在 Apple 平台请求原生实现。两者同时启用时按兼容后端选择。配置宏、系统特性宏及部署目标作为构建级设置，覆盖同一程序使用对应 RandX 头文件的全部翻译单元、静态库和预编译头。

`SecureWipe` 及新增兼容、编译器适配辅助函数采用 `detail` 命名空间中的外部链接 inline 定义，同一配置下各翻译单元具有相同定义和名称绑定。审查 `ScopedWiper` 与 ChaCha20 inline 定义所依赖的擦除名称，满足 [ODR](https://eel.is/c++draft/basic.def.odr)。CMake 提供同名布尔选项，默认关闭，启用时向对应 INTERFACE 目标传播值为一的编译定义；直接包含头文件的消费者通过统一编译选项设置，API 文档说明这些配置契约。

### 3.4 后端测试接口与能力验证

兼容实现可在内部测试中直接调用。独立审计目标以目标私有编译选项启用 `RANDX_USE_PORTABLE_SECURE_WIPE`，验证 `SecureWipe` 和实际生命周期调用；该配置覆盖目标的全部翻译单元。熵源 hook 仍仅属于既有独立故障目标，生产 INTERFACE 目标保持生产配置。

能力验证使用实际包含生成头文件的小型编译链接样例，并记录选中的后端。每种生产配置至少链接两个翻译单元，分别直接包含 RandX 和预先包含系统头，执行共同擦除及生命周期调用；普通和 LTO 构建均验证。ODR 同时进行来源审查，链接成功仅作为集成证据。

## 4. 优化构建审计

### 4.1 两类证据

运行时测试使用仍存活的数组，核对零长度、非对齐起点、不同长度、区间外哨兵字节，以及守卫正常退出和异常展开。调用方存储寿命结束后，不读取对象或栈地址。

防删除探针使用运行时输入构造敏感材料，在擦除前完成可观察的消费，擦除后不再读取材料。保留可定位的探针函数，检查最终链接产物，而非只检查源代码、未链接汇编或函数名。探针自身可为定位保留函数标记，生产擦除函数不因审计额外禁用优化。

现有数组读回测试会让擦除结果成为可观察行为，不能单独证明“无人再读取的数据”在优化后仍被擦除。

### 4.2 构建与判定

| 编译器 | 必需配置 |
| --- | --- |
| GCC／Clang（Linux） | Release 优化、Release 加 `-flto`，两标准、当前声明环境可用的原生后端及显式兼容后端 |
| MSVC | `/O2`、`/O2 /GL` 加链接 `/LTCG`，两标准及原生／兼容后端 |
| MinGW GCC（Windows） | Release 优化、Release 加 `-flto`，两标准及原生／兼容后端 |
| Apple Clang | Release、Release 加 LTO，两标准，默认兼容与构建级显式原生配置 |

脚本记录源码基点、编译器版本、完整命令、后端、标准、架构、链接产物和反汇编。检测到编译或链接失败时返回失败，缺少审计工具不能登记为通过。

审阅擦除调用或实际写入指令，以及对应目标地址、长度和执行顺序。函数可能内联或被系统实现替代，因此不能仅搜索 `SecureWipe` 符号。首次实施及编译器、后端、探针变化时人工确认最终机器码，并在验收文档记录具体证据位置；CI 持续验证构建、功能及已确认的探针检查规则。

用隔离来源副本将擦除替换为空操作，确认对应机器码检查能够识别擦除缺失。该辨别能力测试不能通过擦除后的数组读回来强制保留存储。生命周期探针覆盖局部重播种材料、旧缓存、移动双方状态与析构存储。

### 4.3 检查器规则与辨别能力

检查规则以编译器、架构、标准、优化模式和后端为键登记。先在代表性的 Release 与 LTO 配置中完成人工审阅和变异验证，再扩展必需矩阵。探针包含两类入口：运行时指针与长度的直接擦除，以及运行时材料驱动的局部数组／ChaCha20 生命周期。存储保持普通类型，擦除前消费产生可观察结果，擦除后结束使用。

每个探针记录目标存储区、消费点、擦除点及预期字节范围。直接入口按 ABI 追踪指针和长度参数；局部与生命周期入口结合最终产物的调试信息及反汇编确认栈槽或对象字段偏移。检查器对消费之后的擦除执行以下判定：

1. 原生调用：确认调用目标、目标指针及长度，覆盖登记的字节范围。
2. 内联写入：逐路径追踪实际零写、目标地址和已覆盖字节，确认每条相关退出或覆盖写入路径均在消费之后完成完整擦除。循环核对入口地址、结束地址、步长、字节范围和回边；条件分支只在常量关系已证明时收窄。
3. 局部数组及异常退出：用最终产物 DWARF 的具名变量位置绑定栈存储，用 PE 中的 GCC LSDA 关联受保护调用区间及异常落地点；正常返回和异常传播分别验证。
4. 多个擦除点：逐点判定，分别核对重播种材料、旧缓存、移动源／目标和析构存储；保留源调用点到最终产物位置的证据映射。

每个登记配置的正常实现与空操作变异使用相同编译链接选项和同一检查规则。除全局空擦除外，分别删除一个生命周期擦除点，确认检查器能报告该点缺失；仅当该变异对应检查项明确失败时，才认定变异被检出。其他初始化和剩余擦除存在时仍须拒绝变异，构建报错、无关项失败和对应项无法判定均不能作为检出证据。规则按地址关系、范围和执行顺序识别，不依赖两份产物具有相同的绝对地址或栈布局。

脚本将构建失败、辨别能力失败和无法判定分别报告为失败；仅在全部登记探针通过时返回成功。未识别的机器码形态交由人工审阅更新规则，再运行同配置变异验证。工具测试覆盖正常、单点缺失、全局空擦除、仅有初始化、工具缺失及无法判定的输出与退出状态。

## 5. RandTriangular 公开契约

提供 `RandTriangular(min, peak, max)` 和 `RandTriangular(engine, min, peak, max)`。参数类型一致，支持 `float`、`double`、`long double`，模板顺序沿用现有分布重载。参数全部显式提供，不添加预设区间或对称重载。

| 输入情况 | 行为 | 随机消耗 |
| --- | --- | --- |
| 任一参数为 NaN／无穷，`min > peak` 或 `peak > max` | 抛 `std::invalid_argument` | 不调用引擎，默认重载也不获取默认引擎 |
| `min == peak == max` | 返回该值 | 不调用引擎，不获取默认引擎 |
| 非退化区间，宽度在返回类型中溢出 | 抛 `std::invalid_argument`，与当前浮点区间政策一致 | 不调用引擎 |
| `min < max` 且 `min <= peak <= max`，宽度可表示 | 三角分布采样，返回有限的 `[min, max)` 值 | 调用一次 `RandCanonical<T>` |

众数可以等于任一端点。相邻可表示端点的半开区间可能只包含下界，结果按浮点量化契约返回下界。零和次正规数均参与正常数值处理，不修改调用方的浮点控制模式。

数值验收采用目标类型的实际浮点格式、向最近值舍入及逐渐下溢。构建采用 GCC／Clang 的标准浮点选项和 MSVC `/fp:precise`，审计记录实际选项及 FMA 收缩设置。`fast-math`、FTZ／DAZ 或其他舍入模式不属于本次精度与次正规验收条件；库保持调用方浮点环境，API 文档说明支持条件。

一次 `RandCanonical<T>` 不等于一次底层引擎取值：当前满位宽 64 位引擎生成 float／double 各调用一次，满位宽 32 位引擎生成 double 调用两次、float 调用一次；其他引擎及 long double 复用现有规则。

默认重载先完成参数与退化判断，再获取默认引擎。引擎在正常采样中抛出的异常原样传播；不对引擎已经完成的取值作状态回滚。

## 6. 数值实现

使用一个 `TriangularKernel<T>` 集中校验、退化状态、宽度、众数比例和分位转换。其采样方法只取得一次均匀值，随后调用纯数值方法；公开重载不复制公式。区间政策与现有 `RealIntervalKernel` 一致，本次保持既有均匀分布内核稳定。

记 `a=min`、`m=peak`、`b=max`、`w=b-a`，众数比例 `c=(m-a)/w`，均匀值 `u` 属于 `[0,1)`。逆变换定义为：

```text
u = 0：        x = a
0 < u < c：    x = a + w · sqrt(u) · sqrt(c)
u = c：        x = m
u > c：        x = b - w · sqrt(1-u) · sqrt((b-m)/w)
```

右支直接计算 `(b-m)/w`，避免从已舍入的 `c` 减出极小尾部。端点众数通过同一分支规则处理，不除以零。端点分支先计算 `u/c` 或 `(1-u)/q`，再开方并乘相应子区间宽度，避免直接形成可能溢出或提前下溢的中间乘积。

纯数值方法接受内部算术类型可表示的有限 `u`，范围为 `[0,1)`，返回类型仍为 T；`u=0` 的规则优先于 `u=c`，覆盖左端点众数。该方法用于内部数值验证，公开采样仅将 `RandCanonical<T>` 的实际输出精确转换到内部类型后传入。满位宽引擎的 float／double 正值网格分别为 `k·2^-24`／`k·2^-53`，网格精度对应现有 canonical 位提取规则；任意分位输入与这些离散网格分别建立用例。极小分位差的验证属于任意分位输入的数值能力，公开采样的性能报告记录实际平方根成本。

float 的内部算术使用 double；double 使用 double；long double 使用其原生类型。先按返回类型检查宽度可表示性，再在内部类型中计算端点差及比例。均匀值仍由返回类型对应的 `RandCanonical<T>` 取得，内部提升不改变随机消耗。两头文件固定相同表达式顺序。

插值按端点与众数之间的距离选择计算起点。令 `L=m-a`、`R=b-m`、`q=R/w`，在左支的 `c/4` 和右支的 `1-q/4` 切换，以保持端点附近的精度和众数附近的单调性：

```text
左支 u < c/4：         a + L · sqrt(u/c)
左支 c/4 <= u < c：    m - w · (c-u) / (1+sqrt(u/c))
右支 c < u < 1-q/4：   m + w · (u-c) / (1+sqrt((1-u)/q))
右支 u >= 1-q/4：      b - R · sqrt((1-u)/q)
```

近众数的表达式由平方差有理化得到；先乘宽度再除分母，保留极小分位差在大区间中的贡献。两种表达式在接点对应 `a+L/2` 与 `b-R/2`。接点两侧以这两个固定的目标类型值分别约束输出，避免两个表达式的独立舍入形成下降。两端点众数沿同一有效分支处理，归一化的分母只在对应非零区间使用。

常量以对应内部类型定义并命名，两标准复用同一实现。极端区间经独立高精度参考验证有限性、误差与单调性。转换到返回类型后，将上界舍入命中纠正为 `nextafter(max, min)`，下界舍入越界纠正为 min。参数有效性、有限计算、接点连续性和浮点边界分别验证。

数学参考采用 [Boost 三角分布的逆变换定义](https://www.boost.org/doc/libs/latest/libs/math/doc/html/math_toolkit/dist_ref/dists/triangular_dist.html)及[实际实现](https://github.com/boostorg/math/blob/develop/include/boost/math/distributions/triangular.hpp)。参考库仅用于开发期核对，不进入消费者依赖。

## 7. 三角分布验证

### 7.1 确定性与数值边界

使用固定输出和计数引擎验证 `u=0`、众数分位点、两侧分位点及最大可生成均匀值。选择具有独立解析期望的分位点，配合高精度参考材料，避免测试重复生产公式。

公开用例从实际均匀网格选取分位点。只有众数比例恰好可由网格表示时，才通过公开采样验证 `u=c` 返回众数；其余情况验证众数比例两侧相邻的可生成均匀值。内部数值用例另外覆盖 `c` 及其可表示相邻值、接近零和一的任意分位点，以及端点／众数计算接点 `c/4` 与 `1-q/4` 两侧的相邻值。跨零、同号巨大端点和极端偏斜参数均覆盖这些切换点。

覆盖端点众数、对称与偏斜分布、负区间、跨零区间、相邻端点、次正规宽度、可表示的巨大宽度及极不对称众数。宽度溢出按约定拒绝；其余合法输入均验证有限性、半开边界与数值误差。

参考生成器从输入浮点值的精确二进制值构建高精度参数，使用数学逆 CDF 及独立 CDF 回代核对，保存高精度分位值和按公开半开边界政策转换的参考结果。Boost 的普通精度实现作为公式参照；极端区间的真值由高精度计算生成。参考从 256 位十进制有效位开始，以 512 位复核，再按倍数增加至最多 8192 位，确认参考结果的目标类型舍入和误差判定稳定，同时将参考计算误差界计入该用例的总预算；记录所用格式、精度、参考来源与生成命令。依赖仅用于 Miniconda 开发环境。

在 `triangular_reference.hpp` 冻结参数、分位点、参考值和具名容差表：普通区间和同号极端端点众数记录局部 ULP 误差；宽度达到最小正规数的跨零区间记录按区间宽度归一化的绝对误差；次正规宽度限制为一个实际量化间距，相邻端点要求离散结果一致。`u=0` 必须精确返回 min。容差依据内部类型各阶段舍入、平方根误差、输出量化及上界纠正推导，记录误差预算，不按候选输出反推阈值。对同一组参数，按递增 `u` 检查最终返回值单调不减；有限性、边界和单调性作为独立硬性条件。参考生成工具运行单元测试及固定解析案例自检。

验证所有非法及退化调用的引擎计数为零；默认引擎状态通过有效调用前后对照及独立进程初始化探针确认。非法默认调用的初始化探针采用生产配置，不能借用熵源 hook 改变被测路径。

固定种子测试同时核对结果与调用后引擎状态。默认与显式重载连续调用等价。当前 `ci.yml` 的 parity 任务在 GCC 14 下逐字节比较 C++17／C++23 生成结果；现有抽样门禁在各工具链下比较基线与候选的抽样行为。三角分布新增同工具链双标准观测，float／double 输出及引擎状态逐位一致，long double 按平台格式登记并比较两标准结果。CI 在 GCC、Clang、MSVC、MinGW 和 Apple Clang 的已登记配置分别执行三角分布数值契约；各工具链之间依据高精度参考及容差验收。既有抽样基线门禁保持原有范围和要求。

### 7.2 统计验证

在标准化区间 `[0,1]` 上，均值为 `(1+c)/3`，方差为 `(1-c+c*c)/18`。参考 [SciPy 三角分布实现](https://github.com/scipy/scipy/blob/main/scipy/stats/_continuous_distns.py)核对解析量，测试统计计算采用更高精度累计或稳定在线算法。

固定种子覆盖对称、左右偏斜及端点众数。均值容差依据标准误差 `sqrt(variance/N)` 加浮点量化误差制定；方差容差依据四阶矩制定。样本量、置信参数、分箱和误差界全部命名并记录推导，实施前冻结，失败后不能重试到通过或调宽门槛。

确定性偏差预算同时包含均匀分位网格、输出舍入及上界纠正。对满位宽 float／double 引擎，按对应网格推导矩和分箱概率相对连续参考的偏差界，将其加入统计阈值；其他引擎及 long double 使用实际 canonical 精度建立预算。常规区间中也须确认这些偏差相对抽样误差的量级。

拟合优度使用独立 CDF 参考计算分箱概率，确保每箱期望频数满足所选检验要求。固定测试集合以预先定义的整体显著性控制多项检验误报。极端可表示区间主要执行确定性数值验证，避免用连续模型否定浮点量化。

### 7.3 性能与文档

新增对称、偏斜、端点众数和退化路径的 Google Benchmark 项，覆盖满位宽 32／64 位引擎。报告每次调用耗时及引擎消耗；不设置缺乏参照的提速比例。新基准按现有策略报告暂无历史值，已有基准继续执行同机回归门禁。

API 文档说明参数顺序、众数含义、半开输出、退化及宽度限制、异常和调用消耗。新增一个模拟场景示例，不引入新随机引擎或安全承诺。
