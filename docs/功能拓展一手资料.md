# RandX 功能拓展一手资料

研究日期：2026-10-05。

研究范围：按仓库当前支持的 C++17 与 C++23 评估逻辑地址随机数、随机访问跳跃、带权无放回抽样和可复用带权选择。本文记录一手资料事实与据此作出的推论，不定义公共 API。[项目标准与接口概况](../README.md)

## 结论

| 能力 | 一手资料与现状 | 值得继续投入的条件 |
| --- | --- | --- |
| 按逻辑地址生成的 Philox | Counter-based 生成把 key 与 counter 映射到输出；相同输入给出相同输出。WG21 的 N4988 C++26 工作草案包含 `std::philox_engine` 与 `set_counter`，N4989 记录 P2075R6 已采纳到 C++ 工作草案。项目当前支持 C++17/C++23；C++23 最终工作草案早于该提案进入工作草案。[Random123 论文](https://www.thesalmons.org/john/random123/papers/random123sc11.pdf)、[WG21 N4988 Philox 条文](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2024/n4988.pdf#page=1511)、[N4989 采纳记录](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2024/n4989.html)、[N4951 对 C++23 最终工作草案的说明](https://open-std.org/JTC1/SC22/WG21/docs/papers/2023/n4951.html) | 需要基于稳定的应用逻辑标识复现结果，且任务可在不同线程数、分块或调度下重排。增量是面向 C++17/23 的可用性及逻辑地址约定；Philox 算法和标准引擎形式已写入后续工作草案。性能收益尚无 RandX 实测。 |
| 任意步数 jump-ahead | C++23 引擎要求的 `discard(z)` 已表达前进 z 次的语义，但标准只要求复杂度不差于连续调用 z 次。xoshiro 作者说明可对线性递推计算任意跳跃多项式；RandX 当前 `jump()`／`longJump()` 是固定步长，`discard(z)` 逐次调用引擎。[N4950 §28.5.3.4 引擎要求](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf#page=1419)、[xoshiro 作者资料](https://prng.di.unimi.it/)、[RandX discard 实现](../RandX.hpp#L360)、[Xoshiro256 跳跃接口](../RandX.hpp#L508) | 只有在现有引擎上为任意偏移提供实测有效的快速定位，或避免 `MakeStreamEngine` 随流编号重复执行 jump 时，才构成超出 `discard` 的增量。单纯包装 `discard` 不增加语义。性能收益待测。 |
| 带权无放回抽样 | C++23 `std::sample` 规定所有大小为 m 的可能样本等概率；`std::discrete_distribution` 则按归一化权重返回单个类别，没有移除已选项的操作。Efraimidis–Spirakis 给出带权无放回抽样算法，并将其定义为每轮按剩余项权重比例抽取。[N4950 §27.7.12 `sample`](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf#page=1358)、[N4950 §28.5.9.6.1 `discrete_distribution`](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf#page=1452)、[Efraimidis–Spirakis 作者稿](https://utopia.duth.gr/~pefraimi/research/data/2007EncOfAlg.pdf) | 这是四项中最明确未被上述标准接口覆盖的行为。推进前必须选定联合抽样律；可作为证据充分的算法起点的是 Efraimidis–Spirakis 的顺序概率比例抽取定义及其 A-Res 单遍算法。性能收益和目标数据规模尚无 RandX 实测。 |
| 可复用带权选择 | C++23 标准分布允许保存 `std::discrete_distribution`，也允许保存 `param_type` 后重复使用；RandX 已提供接受预构建 `std::discrete_distribution` 的 `RandWeighted` 重载。Walker/Vose alias table 是另一种静态权重算法，线性预处理后可常数时间抽取。[N4950 §28.5.3.6 分布要求](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf#page=1422)、[RandX 现有重载](../RandX.hpp#L2717)、[Walker 原论文](https://doi.org/10.1145/355744.355749)、[Vose 原论文](https://doi.org/10.1109/32.92917) | 新增一个只转调标准分布的复用包装已与现有接口重叠。Alias 表只有在大量重复抽取、权重固定，且实测需要标准未保证的抽取时间上界时才有明确增量；修改权重则要定义重建或更新成本。本文没有 RandX 性能测量。 |

优先投入带权无放回抽样的抽样律选择与边界验证；若目标应用需要跨调度复现，再评估按逻辑地址生成的 Philox。任意跳跃只在大 `streamId` 的 `MakeStreamEngine` 构造成本测出为热点后继续；重复带权抽取的通用包装已有标准分布和 RandX 重载覆盖，alias 表应留到固定权重的高频抽取基准显示实际瓶颈时再考虑。

## 关键事实与边界

### 逻辑地址与调度复现

**确定事实：**Random123 论文将第 n 个随机值写为 `b_k(n)`，指出它没有相邻输出的顺序依赖；应用可把粒子编号、体素编号、网格索引等应用变量放入 key/counter，使随机值对应计算对象而非执行线程。论文称这类映射可支持与机器参数无关的流，并便于跨计算平台复现。[论文引言与 API 讨论](https://www.thesalmons.org/john/random123/papers/random123sc11.pdf)

**确定事实：**Random123 官方 CBRNG 文档将生成器描述为 `g(counter, key)` 的无状态纯函数：同一输入对总是返回同一结果；固定 key 时，counter 到输出为双射。官方文档也要求应用避免误用同一 key/counter 对，因为复用会产生完全相同的结果。[Random123 CBRNG 契约](https://www.thesalmons.org/john/random123/releases/latest/docs/CBRNG.html)

**确定事实：**WG21 的 N4988 C++26 工作草案中，Philox 引擎保存 counter、key 与一组缓冲输出，并提供 `set_counter`；N4989 记录 P2075R6 已采纳到 C++ 工作草案。C++23 最终工作草案为 N4950，形成于该提案采纳前。因此本文将 Philox 作为后续标准工作草案的覆盖记录，不将其算作 RandX 当前 C++17/C++23 目标已具备的标准接口。[N4988 §28.5.4.5 Philox 状态](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2024/n4988.pdf#page=1510)、[N4988 `set_counter`](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2024/n4988.pdf#page=1511)、[N4989 采纳记录](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2024/n4989.html)、[N4950 C++23 最终工作草案](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf)、[N4951 编辑报告](https://open-std.org/JTC1/SC22/WG21/docs/papers/2023/n4951.html)

**推论：**调度复现性来自应用将稳定的逻辑坐标映射到不重复的 key/counter，而不是由 PRNG 单独保证。`std::philox_engine`仍是持有当前状态的标准引擎；`set_counter`提供定位能力，但标准并未替应用定义逻辑坐标到 key/counter 的字段映射，也没有把这个映射变成无状态调用。若把物理线程号作为唯一地址维度，线程数或任务分配变化就可能改变映射；若同一逻辑地址被重复使用，则必然重现同一随机值。随机地址的位宽、字段分配、对象标识、对象内抽样序号、重用规则、key 生成规则和算法参数都需要成为明确约束。[标准引擎状态与定位契约](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2024/n4988.pdf#page=1510)、[论文对应用变量和 tuple 不复用的要求](https://www.thesalmons.org/john/random123/papers/random123sc11.pdf)

### 随机访问跳跃

**确定事实：**C++23 随机引擎契约提供 `discard(z)`，定义为将状态推进到等价于调用 `operator()` z 次之后的位置；标准允许实现复杂度与 z 次连续调用相同，并不要求对任意 z 提供次线性跳跃。[N4950 §28.5.3.4 引擎要求](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf#page=1419)

**确定事实：**xoshiro 作者资料指出，其基于线性递推的生成器可以用跳跃多项式模拟任意数量的状态转移；项目当前 xoshiro 的 `jump()`／`longJump()` 使用两种预设距离，而共同 `discard` 实现循环调用生成器。`MakeStreamEngine` 也通过重复调用 jump 构造流状态。[作者说明](https://prng.di.unimi.it/)、[RandX discard 与 jump 实现](../RandX.hpp#L360)、[MakeStreamEngine](../RandX.hpp#L4364)

**推论：**任意步数定位在语义上不是新能力，因为标准已有 `discard`；可能新增的是在 RandX 已有引擎上提供有证据的快速定位算法，或降低大流编号的构造成本。值得性取决于真实偏移分布、前处理/缓存成本和两标准版本的状态与输出序列一致性；尚无本项目性能数据。

### 带权抽样与复用

**确定事实：**C++23 `std::sample` 为输入范围中所有大小为 `min(N,m)` 的可能样本规定相同概率，复杂度为 O(N)；其规范没有权重参数。`std::discrete_distribution` 则按 `p_i=w_i/Σw` 返回 `[0,n)` 中的单个整数，权重要求非负、有限且总和为正。[N4950 §27.7.12 `sample`](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf#page=1358)、[N4950 §28.5.9.6.1 `discrete_distribution`](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf#page=1452)

**确定事实：**C++23 标准分布拥有 `param_type`、`param()` 与 `operator()(g, p)`，允许调用方持有分布参数并重复抽取。标准只约束每次抽取平均调用随机引擎的次数，不规定按类别数计算的查找复杂度，也不要求使用 alias table。[N4950 §28.5.3.6 分布要求](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf#page=1422)、[N4950 §28.5.9.6.1 `discrete_distribution`](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf#page=1452)

**确定事实：**Efraimidis–Spirakis 的定义是重复 m 轮：每轮在尚未选中的集合中，按 `w_i / 剩余权重总和` 抽取一项；其 Algorithm A 为每项生成 `u_i^(1/w_i)` 键并取最大的 m 项，Algorithm A-Res 将该过程改造成大小为 m 的单遍 reservoir。作者稿假设严格正权重与无限精度随机数；零权重、浮点端点、非有限值和退化输入需要额外的实现契约。[作者稿中的定义与算法](https://utopia.duth.gr/~pefraimi/research/data/2007EncOfAlg.pdf)、[期刊论文页面](https://doi.org/10.1016/j.ipl.2005.11.003)

**确定事实：**Walker 的离散 alias 方法与 Vose 的改进处理的是给定静态离散权重下的重复抽取；Vose 论文摘要明确给出 O(n) 初始化和常数时间抽样。它们不等同于从样本中移除项目后的带权无放回选择。[Walker](https://doi.org/10.1145/355744.355749)、[Vose](https://doi.org/10.1109/32.92917)

**项目现状：**RandX 的 `RandWeighted(weights)` 会校验并预处理权重，再调用 `std::discrete_distribution`；另有接受预构建标准离散分布的重载，供重复抽取复用。RandX 对空容器、全零、负数和非有限权重有自身行为；而标准离散分布对空权重序列规定为单元素、概率为 1。比较复用能力时应以现有预构建重载为基线，并单独核对输入验证边界。[RandX 权重预处理](../RandX.hpp#L2618)、[RandWeighted 与预构建分布重载](../RandX.hpp#L2705)、[N4950 §28.5.9.6.1 `discrete_distribution`](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf#page=1452)
