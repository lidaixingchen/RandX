# 抽样内核收拢验收结果

日期：2026 年 10 月 2 日

行为基点：`e0ce50a`

候选：当前工作区的 `RandX.hpp` 与 `RandX_Cpp17.hpp`。

## 1. 实现

两份独立头文件分别拥有一个完整随机访问抽样内核和一个完整蓄水池抽样内核。四个迭代器公开重载保留原有类型提取、约束与距离计算，以局部迭代器、哨兵引用调用内核。容器数量转换、默认引擎访问、位图路由及 ranges 适配保持现有职责。

静态获取器保留延迟获取阶段；固定分布策略保留默认 hash-set 的复用和显式 hash-set 的逐次构造。动态区间每步构造同一入口策略适配，默认入口持有该步的分布对象，显式入口沿用 `RandInt` 的逐次构造。两个内核在公开适配层展开，公开入口采用常规 `inline`；整型差值的空请求使用适配层快路径，标注宏在抽样区域末尾解除。

算法阈值、分配位置、元素复制与赋值方式、随机数消耗和结果顺序保持基点行为。公开 API、独立包含方式与安装结构保持一致。

## 3. 性能与构建成本

Google Benchmark 为 v1.8.5。两边使用相同的候选基准源与构建配置，只替换生产头文件包含目录。C++17 与 C++23 各注册 243 个抽样测量项：237 个核心参数项及 6 个位图字边界项，覆盖默认与显式入口、64/32 位引擎、小范围及大范围、hash-set/索引数组/位图/蓄水池、阈值邻接、高密度、零量与全量请求。四份基准程序的案例集合一致，核心参数项完整保留。

输入准备和默认引擎预热在计时循环外。每次循环通过 `DoNotOptimize(request)` 保留运行时输入，结果通过数据指针观察，有元素时通过内存屏障观察缓冲区写入。每项最小测量时间为 `0.1s`；每组运行五轮，基点与候选交替，偶数轮反转顺序。保留单轮 JSON，并以 `tools/merge_benchmark_repetitions.py` 生成 median，使用现有 `tools/compare_benchmark.py --tolerance 0.25` 判断项目门禁。

抽样性能程序使用 CMake Release `-O3 -DNDEBUG`，固定逻辑处理器 2，使用 Windows High 进程优先级。两标准各 237 个核心参数项的五轮测量完成，测量项集合一致。初次 `0.1s` 比较中，C++17 有 3 项、C++23 有 11 项超出 25% 容差。对这些项目及一个关键路径共 14 项，使用每项 `1s`、同处理器与优先级、五轮交替完成延长测量，两标准均通过门禁。

位图字边界参数从 `SampleBitmapWordBits` 推导：对齐长度 256，其相邻长度为 255、257；按密度除数推导请求量 128、127、128。三个容器入口分别使用默认、显式 64 位及显式 32 位引擎，均进入位图路径。对齐长度已在核心矩阵中，另外 6 项各完成 `1s`、五轮交替测量。默认容器长度 1000000、请求 245 的临界项也按同一配置延长测量。

最终验收包含 243 项：14 个核心疑点、6 个边界项及一个临界项采用延长测量中位数，其他 222 项采用核心矩阵测量中位数。双边采用相同选择规则；`build_sampling_review_fixes/benchmark/accepted-*.json` 逐项记录来源，全部原始结果与初次比较失败记录保留。两标准各 243 项的最终比较退出码均为 0。

单组行为比较：

```powershell
D:/Miniconda/python.exe tools/compare_sampling.py `
  --baseline-ref e0ce50a --candidate-root . `
  --compiler g++ --compiler-family gcc --standard c++23 `
  --build-mode release --output-dir build_sampling_compare
```

同源抽样基准：

```powershell
cmake -S . -B build_sampling_candidate -DRANDX_BUILD_BENCHMARK=ON `
  -DCMAKE_BUILD_TYPE=Release -DRANDX_SAMPLING_HEADER_DIR="$PWD"
cmake --build build_sampling_candidate `
  --target benchmark_gbench_sampling_cpp17 benchmark_gbench_sampling_cpp23
```

将相同命令的构建目录和 `RANDX_SAMPLING_HEADER_DIR` 分别换成基点构建目录、基点头文件目录，即可构建对应基准。正式 CI 自动固定双边源文件、依赖、轮数和比较参数，并保存原始测量。
