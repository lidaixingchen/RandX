# 编译器属性收敛验收

验收日期：2026-10-04。生产代码提交为 `52b0ceca6e820c728a0255b5901c3855c8b78796`。源码的清晰程度、常规表达和可维护性优先于局部计时，性能回归同时记录相对增幅与绝对耗时。公开参数契约、算法、随机消耗与输出序列保持一致。

## 当前实现

稠密抽样通过公开入口校验请求数量，内核使用普通循环和标准库整数分布。默认洗牌采用普通 `inline`，直接调用 C++17 的 `std::shuffle` 或 C++23 的 `std::ranges::shuffle`。洗牌函数及其标准库调用的内联由编译器自行决定。

默认引擎冷构造、稠密分派、抽样适配器、位图、分布包装和其他操作的现有边界见[性能策略评估](整数生成性能策略评估.md)；它们各自的贡献仍须独立判断。[`flatten` 的 GCC 定义](https://gcc.gnu.org/onlinedocs/gcc/Common-Attributes.html)是尽可能内联函数体内的调用，保留 `noinline` 边界，并不保证循环展开或函数自身内联。本报告涉及该属性的配置仅用于机制与吞吐对照。

## 本地成对测量

环境为 Windows 11、Ryzen 7 5800H、MinGW GCC 16.1.0、libstdc++ 16、Google Benchmark 1.8.5，双标准均使用 `-O3 -DNDEBUG -falign-functions=64 -falign-loops=64`。每组在同机同配置下编译参考与候选，交替 AB／BA 顺序，初测五轮、每项 0.1 秒，确认六轮、每项 1 秒。仅测量子进程绑定 CPU 15 并采用高于普通的调度优先级。主机系统版本与 CPU 型号的核对结果、采集时间在原始材料中单列，采集晚于计时。

计时消费者复用正式抽样正文，另注册 `mt19937_64` 与两个默认洗牌规模，每个配置共注册 326 项。洗牌测量覆盖 256 和 65,536 个元素；上界对照覆盖随机访问容器／迭代器、256 和 1,000,000 的总体，以及四种引擎，延长确认覆盖默认引擎和 Xoshiro256 的代表项。CPU 与实际时间逐轮分别保留，下表使用 CPU 时间中位数，正值表示候选更慢。各组参考提交在原始材料中分别注明，不能跨组拼接绝对耗时。

| 对照配置 | C++17 确认变化 | C++23 确认变化 |
| --- | ---: | ---: |
| 公开洗牌入口仅 `always_inline`，内部普通 `inline` | +87.49% 至 +92.55% | +85.15% 至 +92.82% |
| 公开洗牌入口 `always_inline` 与 `flatten`，内部普通 `inline` | −0.58% 至 −0.12% | 0.00% 至 +1.79% |
| 公开入口仅 `always_inline`，内部仅 `flatten` | +0.39% 至 +0.64% | +1.21% 至 +1.69% |
| 稠密内核普通上界表达 | −2.14% 至 +3.48% | −32.48% 至 +4.60% |
| 直接标准库洗牌，普通 `inline` | +78.78% 至 +93.76% | +89.81% 至 +95.32% |
| 直接标准库洗牌，普通 `inline` 与一处 `flatten` | +11.72% 至 +21.66% | +11.98% 至 +22.63% |

上界对照的 C++23 个别大请求轮次离散明显，较低的中位数不能据此认定稳定收益。洗牌属性存在交互：在另一层属性保留时，单项移除可能没有改变生成代码；多项同时变化时，标准库分布调用边界会发生变化。因此，[前一轮单项实测](抽样与洗牌编译器属性实测.md)与本轮组合对照须一起读取。

当前洗牌配置的绝对耗时如下：

| 标准 | 元素数 | 参考（ns） | 当前（ns） | 变化 |
| --- | ---: | ---: | ---: | ---: |
| C++17 | 256 | 299.07 | 534.67 | +78.78% |
| C++17 | 65,536 | 76,136.06 | 147,524.11 | +93.76% |
| C++23 | 256 | 293.49 | 557.08 | +89.81% |
| C++23 | 65,536 | 75,263.81 | 147,004.24 | +95.32% |

参考配置将整个洗牌循环内联到基准函数。当前 C++17 基准调用独立 `std::shuffle`，C++23 基准将标准库洗牌正文内联，均留下循环内的分布外调。仅公开入口强制内联的配置也出现循环内分布外调。单处 `flatten` 对照中的独立洗牌函数分别有 267／269 条指令，唯一显式调用是默认引擎冷构造函数。指令数量及调用目标用于解释编译器机制，不直接等于吞吐成本。普通洗牌相对于参考的耗时增加约 79%–95%，属于明显的性能代价。

五组实验共保存 264 次测量进程、952 条原始记录；初测与确认共 88 个比较项均由逐轮 JSON 核对中位数及变化公式。22 个双标准功能配置的完整输出和最终引擎状态逐字节一致，每个配置为 2,071,392 字节。固定种子验证覆盖 66 个抽样／洗牌组合，总体为 256 和 65,536，不能代替百万元素计时用例的完整契约验证。
